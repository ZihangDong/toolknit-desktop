# V3.2 常见非扫描 PDF 转 Word 适配

日期：2026-10-20（Asia/Shanghai）。当前版本3.2.0、分支`codex/v3.2-history`，保持未发布。用户明确授权新目标，要求至少6小时的实际适配、实测对比与优化；不以空等凑时长，不在目标未达成时以达到时长为由宣布完成。

## 目标与范围

在已有引擎上适配大众使用的微复杂非扫描PDF：论文、发票、合同协议、文章/图文资料、电子书、表格与报价单。正文尽量可编辑，关键信息完整对应，常见表格能修改，版面无明显重叠、截断和异常分页；允许轻微字体间距差异。印章、二维码、插图和难处理的小区域可局部图像保真；普通文字型整页图片不计为编辑性通过。

沿用已有公式局部图像保真，不开展新的原生公式研究或扫描OCR。电子书先按现有300文档页、单次100页与容量限制验证，不为单一样本无依据放宽上限。开发默认本地离线，不上传私人文件或调用收费AI。本轮不打包、提交、推送、发布、升版或修改用户文件。

## 验收维度

- 内容：金额、日期、条款/列表编号、名称和字段对应原稿；文字不得被AI或推断逻辑改写。独立抽查实际DOCX文字与原稿，不只看引擎来源账本。
- 编辑：正文可选择修改；表格的文字可编辑和真正Word表格分别记录。整页或大块图像回退明确报告。
- 版面：标题、段落、栏、图注、表格和页眉页脚关系合理；不追求100%像素一致。视觉辅助分数不代替内容审查。
- 阅读器：WPS为主要验收环境，LibreOffice分别记录；不将桌面结果外推为Word、手机WPS或微信通过。
- 运行：输入限制、页范围、取消/重开、内存资源清理、失败反馈、原生保存及输出不覆盖原件。

## 进展记录

### 第一轮开发与实际渲染

本地证据保存在忽略目录`tmp/pdf-word-general/`，权威输入清单为`manifest-complete.json`。每份输入记录来源、SHA-256及选页，开发/验收划分预先固定；7份验收样本尚未用于修补。扫描型来源在基线前按输入类型排除。测试未上传用户文件。

- 字体：不认识的嵌入字体按PDF.js确认的serif/sans-serif/monospace选择稳定替代字体，保留明确字体别名优先级。77页电子书正文不再误用手写体，WPS页数保持77，前景像素辅助指标均值由约76.42%提升至99.74%；可编辑101,347/101,614字符。这是外观指标，不是内容正确率。
- 字体边界：无效零字体度量不再当成不可见文字；无轮廓时给实际裁图保留有限斜体外伸范围，不放宽缺墨门禁。TAMReview由失败恢复为23页可生成且WPS外观可读，但因源编码损坏仅4,405/50,102字符可编辑，明确不计作正文编辑性通过。
- 批注与图案：边界明确、位于正文后的批注外观及有限填充图案使用局部保真；未知图形状态仍保守降级。图文样本由整页图片提升为1,423/2,495字符可编辑。遮盖内容不可重新暴露，空批注不可吞掉正文。
- 表格：当前16页多页表格WPS仍为16页，前景像素均值99.80%，但只28,904/49,435字符可编辑；继续查明降级。部分彩色/合并/旋转文字表格外观通过，不据此宣称原生Word表格成功。
- Node Canvas对一个中文发票的NUL字形抛出InvalidArg；此前真实浏览器路径可转换，需要重建后复测，不能将测试后端限制误报为产品故障。

聚焦测试已覆盖字体替换、缺失轮廓的斜体外伸、批注遮盖/空外观/非法边界、图案及原有表格图层。当前仅为阶段进展；全量门禁、独立样本、更新后的浏览器和LibreOffice验证未完成。

### 表格与独立样本复核

- 发现整页组行把靠近列线的相邻单元格合并。`core/tables.js`改为按已确认的网格逐格组行，16页表格恢复为16个原生Word表格，可编辑49,380/49,435字符。实际WPS仍为16页，均值99.6691%、最低99.5641%；首尾页目检未见日期、金额、行列关系错位。合成回归检查实际DOCX的单元格内容，不只检查内部布局。
- `core/graphic-text-layers.js`在已验证绘制映射下恢复普通背景文字，复用每页最多4个背景层与一次附加渲染；不改变资产容量。重叠裁图不能残留第二份旧文字，复杂公式、上下标及实际遮盖继续保留原图。初步图文能源报表由81提升为891个可编辑字符，仍不算正文编辑性完整通过。
- 中文发票真实UI暴露边缘异常字形使裁图超出表格约1.4pt的问题；保留逐单元格归属，仅对识别图像归属允许有界小幅外伸。真实UI恢复为214/599可编辑字符，WPS保持1页，浏览器Canvas实际原稿对照98.6019%；源文件包含NUL及遮盖/印章，编辑限制明确保留。比原218字符略少，不能宣称全部恢复。

### 真实页面批量验证及运行路径差异

- 上一阶段完整发布门禁104个脚本通过，包含1488项安全检查、CLI和产物审计；Rust为250 passed、9 ignored，原生验证器使用实际100页UI导出的DOCX。干净工作区子项仍验证已提交V3.1，不冒充当前V3.2的干净安装。私有Skill新增已验证维护经验并通过验证。
- 将30份样本全部走生产构建中的实际页面，首次结果为28份导出、2份失败。发现Node与浏览器PDF.js默认字体策略不同：浏览器优先系统替代字体，缺少字形轮廓，导致16页表格在实际UI中只有369字符可编辑，而Node为49,429；TAMReview缺墨校验失败，Brotli图片容量超限。因此此前Node数据不能直接作为产品UI验收结果。

### 表格边界、白字及装饰裁剪
