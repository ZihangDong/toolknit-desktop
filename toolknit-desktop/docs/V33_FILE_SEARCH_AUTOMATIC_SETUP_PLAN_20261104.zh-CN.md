# V3.3 文件搜索：自动配置与浮窗修复方案

日期：2026-11-04。状态：已实施并完成本机验收，证据与环境覆盖限制见 [实施记录](V33_FILE_SEARCH_AUTOMATIC_SETUP_IMPLEMENTATION.zh-CN.md)。

本文保留规划时的源码调查与验收要求；规划阶段未修改产品代码、安装服务或扫描用户磁盘。用户随后批准并创建实现目标。此前单屏验收仍然有效；本次发现的“操作筛选菜单后收起闪现原生窗口”是新增回归场景。

## 1. 建议交付形态

- 第一次进入：居中的 ToolKnit Logo、简短说明、带盾牌图标的「启用快速搜索」按钮。用户点击后完成 Windows 管理员授权，自动准备搜索。
- 正常使用：搜索框、后缀筛选、排序、结果列表、桌面胶囊开关，以及简短的后台整理状态。
- 移除可见的「搜索范围」「全盘加速」配置模块；范围、排除规则和索引方式由程序管理。
- 自动覆盖当前账户可访问的在线磁盘。支持加速的 NTFS 卷自动加速，其他类型自动使用普通索引；不向用户提供磁盘勾选题。
- 去掉主页面搜索输入框的黑色底线；彩色文件类型图标在工具页和浮窗保持一致。
- 继续保持：仅搜索文件名称及路径；结果只提供定位文件；原文件不修改；完全退出停止维护，托盘运行继续，下次启动补齐。

“全盘”表示所有符合固定策略、当前账户可见的范围，不表示越权读取、扫描未连接的设备或发现整个局域网。

## 2. 源码调查结论

| 已核实的事实 | 位置 | 对方案的影响 |
| --- | --- | --- |
| 默认范围只有桌面、文档、下载 | `src-tauri/src/native_runtime/file_search/service.rs` 的 `default_roots` | 必须实现自动发现，不能只隐藏现有配置面板 |
| 当前排除规则只有搜索器自身缓存 | `file_search/storage.rs` 的 `Store::excludes` | 需要统一的范围与排除策略，且覆盖所有索引入口 |
| 加速按盘分组，一个盘失败会中止后续组 | `file_search/index_fast.rs` 的 `run` | 全盘模式应按卷隔离失败，其他盘继续 |
| 服务按需启动，账户已获启动/停止/查询权限 | `file_search/accelerator/install.rs` | 常规启动可不再请求管理员，不必让整个应用提权 |
| 当前服务是否“最新”依赖主 EXE 的完整哈希 | 同文件 `current` | UI 变化也可能要求替换服务，不能承诺现状下一劳永逸 |
| 普通递归跳过重解析目录，每 300 秒统一修复 | `file_search/index.rs` | 自动全盘需单独处理云盘标记、挂载卷和重扫成本 |
| 内存目录已有 500 万条限制 | 同文件 `LIMIT` | 需要全盘规模、内存压力和明确的不完整状态验证 |
| 两个筛选是网页内自定义下拉 | `src/tool-custom-select.js`、`features/file-search/results.js` | 截图里的系统标题栏不是下拉组件本身 |
| 原生窗标题为 ToolKnit File Search；结果窗为 500×406 | `file_search/windows.rs` | 与截图主体尺寸吻合，优先调查结果 HWND 收起链路 |
| 结果窗先网页淡出，再延迟 140ms 隐藏；胶囊变形为 320ms | `window_animation.rs`、`floating.css` | 涉及网页绘制、焦点、原生隐藏的先后关系 |
| 全局输入样式强制绘制底部渐变线 | `src/styles/components/input-focus.css` | 在共享入口提供明确的无底线变体，不能仅覆盖 input 的 border |

这些是代码事实。尚未对本次菜单操作场景做原生逐帧复现，不能把下述闪现假设写成已经验证的唯一根因。

## 3. 原生标题栏与深色矩形闪现

### 判断与调查路径

截图包含系统标题、最小化/最大化/关闭按钮，说明问题进入了 Windows 非客户区绘制，而非单纯 CSS 背景色。操作下拉会让结果窗口取得焦点；收起同时涉及关闭下拉、移出焦点、网页透明、窗口隐藏与原生状态同步。

当前使用 Tao 0.37.1。其 Windows 顶层窗口样式仍包含 `WS_CAPTION`，无边框效果由消息处理实现；`WM_NCACTIVATE` 交回默认处理，窗口状态更新还可能重设 style 并触发 `SWP_FRAMECHANGED`。这解释了“创建时 decorations(false)，中间帧仍可能出现原生边框”的风险，但尚不能据此断言 Tao 单独造成全部现象。

重点检查三段：结果窗获得/失去焦点时的非客户区重绘；WebView 淡出和 HWND 隐藏之间的空档；框架可见状态与 Win32 不激活显示的同步。现有代码没有专门的 700ms 等待，几个延迟也不能简单相加当作用户观察的时长。

### 拟实施策略

1. 用隔离窗口复现“开后缀/排序 → 选中或不选中 → 点收起/点外部/Esc”。记录相关 HWND 的焦点、显示、非客户区绘制和关闭代次，结合连续画面判定闪现发生在哪一步。
2. 只针对文件搜索的三个辅助窗口，评估关闭 DWM 自带窗口过渡。保留 ToolKnit 自己的胶囊动画；不更改用户系统动画、显卡设置或其他工具窗口。
3. 统一关闭事务：先结束菜单及其焦点恢复，再让结果区失去交互，完成短淡出后由主线程隐藏真实 HWND。用代次隔离迟到回调，避免隐藏后又被旧布局显示。
4. 核对原生隐藏与框架状态同步顺序；必要时增加辅助窗专用的非客户区保护。不能只反复调用 decorations(false)，也不能在全局粗暴清除所有窗口样式。
5. 若某类系统的透明合成仍不稳定，结果卡片使用直接原生隐藏的降级路径，保留输入胶囊形变；优先消除标题栏和深色矩形。不能通过扩大窗口、遮住桌面或每次销毁重建来掩盖。
6. CSS 动画结束通知配合有界兜底收尾；业务关闭不能只依赖 transitionend，减少动态效果、后台节流和快速反向点击都须可结束。

验收：打开两个筛选后，选中/取消/交替操作并收起，整个过程不出现系统标题栏或深色矩形；连续 100 轮不复活旧窗口、不抢回外部焦点。同时保留滚动、20px 间隙穿透、圆角、截图联动与原有菜单行为。

## 4. 首次引导与管理员授权

正常流程：未启用 → 点击启用 → Windows 授权 → 校验服务 → 自动发现范围 → 后台建立索引 → 搜索界面。处理中即时反馈、按钮防重入；已经得到的结果可以先搜索，不要求等待所有盘结束。

引导文案建议：

> 快速找到电脑里的文件
>
> 完成一次管理员授权，我们会自动准备文件索引。仅在本机记录文件名和位置。
>
> 启用快速搜索

“一次授权”的准确边界：首次安装辅助服务需要管理员；之后在同一账户正常打开、重启电脑、停止再启动服务，通常不再弹 UAC。服务更新、迁移安装位置、换 Windows 账户、被移除或被企业策略限制时，仍可能需要授权。

实施时将服务兼容版本与主程序 UI 版本解耦，保留受保护安装目录、完整性校验、SID/管道身份和最小权限。不能为了少弹 UAC 去掉哈希校验，或让普通进程可替换高权限程序。服务本体更新优先纳入安装器已有的授权事务；无法复用时明确提供一次修复授权。

- 取消 UAC：停留引导，可重试或返回，不循环弹窗，不写入成功标记。
- 已有可用服务：检查兼容与身份后复用，无需重复安装。
- 没有可加速文件系统或服务不可用：采用普通索引，并说明“当前使用普通搜索”；不能假装全盘加速成功。
- 安装中途关闭工具：后台安装有明确归属；迟到结果不得把用户拉回页面，重新进入读取实际服务状态。
- 旧用户迁移：新增自动模式和策略版本，保留旧偏好备份与胶囊位置/开关。首次切换自动范围仍展示简短启用说明，不在版本升级后台悄悄扩大原来的自定义范围。
- 「搜索范围」「全盘加速」不再出现。暂停后台整理、重建索引等维护操作收进一个简洁的更多菜单，不要求普通用户配置。

## 5. 自动范围与固定排除规则

### 设备处理

| 来源 | 默认处理 |
| --- | --- |
| 在线本地固定盘 | 自动纳入；可用 NTFS 自动加速，其余普通索引 |
| 已连接的移动硬盘/U 盘 | 自动识别；拔出标记离线，重连按卷身份校验并补齐，不混用复用盘符的旧数据 |
| 挂载目录、没有盘符的卷 | 按卷身份去重；当前服务只支持盘符，需扩展卷定位或明确走普通索引，不能悄悄遗漏 |
| 已连接的映射网络盘、旧版明确配置的共享目录 | 普通权限隔离进程、有界超时；本地结果优先，不探测整个局域网、不索取网络凭据 |
| 云盘同步目录 | 只读取本地可见元数据，不主动下载云文件；区分云同步重解析标记与普通链接/循环 |
| 未挂载/锁定/无权限/恢复分区 | 不尝试解锁、提权遍历或挂载；不作为正常可搜索范围 |

当前只枚举盘符和统一跳过重解析目录不足以完成上述要求。发现、去重、监听和重连应以稳定卷身份为依据；目录链接不能导致重复扫描或递归循环。

### 固定过滤

排除的是明确的系统内部数据和缓存，不声称已经有统计证据能定义“99% 用户用不到”。不提供复杂配置页面，但默认规则必须保守，避免造成“明明有这个文件却永远搜不到”。

| 默认排除/降噪 | 必须保留 |
| --- | --- |
| 实际 Windows 系统目录、回收站、System Volume Information、恢复与升级残留目录 | 桌面、下载、文档、图片、视频、音乐及所有普通数据盘目录 |
| pagefile、hiberfil、swapfile 等明确的系统工作文件 | 用户的安装包、压缩包、备份、设计素材和工作文档 |
| 已识别的系统/用户临时目录、浏览器 Cache/Code Cache/GPUCache、崩溃转储 | 微信/QQ 接收文件、云盘可见文件；不排除整个 AppData 或 ProgramData |
| .git 对象与日志、node_modules、.venv 等明确依赖或元数据目录 | 项目源码、配置、README，以及可能存放交付物的 build/dist/target；不按这些通用目录名一刀切 |
| ToolKnit 自身索引、已识别的运行时/模型缓存 | 用户使用 ToolKnit 生成的输出文件 |

Program Files 等安装目录不整棵排除；程序与其他可用文件保留。相关性排序可优先用户资料，系统/应用资源降权；用户选择名称、大小、时间排序时仍遵守对应排序。

规则按已知系统路径和完整目录段匹配，兼容大小写，不误伤名字相似的普通文件夹。预期排除不计为索引失败。

同一策略必须贯穿普通遍历、NTFS 首扫、USN 增量、文件监听、共享目录、缓存加载及查询。服务端在权限查询/返回前尽早过滤不需要的范围；规则有版本指纹，变更后清除过期索引项并重建相应范围，不能只在 UI 隐藏结果。

### 全盘性能所需调整

- 常用目录优先，复用缓存，分批发布；首次建索引的真实进度和已有可用结果分别展示。
- 每盘独立取消、错误和降级；一个盘失败不能阻断后续盘。
- NTFS 优先用 USN 补齐；不把当前每 5 分钟的全范围修复直接扩大为全机反复重扫。普通/网络范围分批低优先级校正，事件风暴有背压。
- 更新后准确处理改名、跨范围移动、权限变化、离线、磁盘复用、缓存损坏和规则升级。
- 500 万条及内存限制必须显式反馈覆盖状态，不能静默截断后显示“全机已就绪”。
- 既有 C/D 服务用例是在限定样本范围内完成，不能据其耗时承诺全机首次索引也是数秒。扩大范围后要重新测 ACL、路径恢复、缓存和峰值内存。
- 参考现有百万条真实 WebView2 合成测试，输入总等待 P95 曾在约 199–237ms 波动；新方案需同机同条件比较，报告包含防抖的总等待，不只报告搜索核心耗时。

## 6. 页面与彩色图标

引导居中相对于工具内容区，而非整个含导航窗口。浅色白底，深色使用现有主题表面；复用记录模式 Logo。授权成功后用短淡入切到工作台，避免布局突然跳动。搜索页不显示大段配置说明，后台状态只占一行。

主页面搜索框采用柔和填充圆角容器。去除默认与聚焦两态底线，不改全局所有输入框；通过共享输入样式的显式变体接入。键盘焦点以轻微容器色差/内侧标识表达，高对比度模式保留系统可见焦点。

| 图标方案 | 已核对的许可与特点 | 建议 |
| --- | --- | --- |
| Material Icon Theme | 仓库 MIT；文件类型覆盖齐全，小体积 SVG；已读 PDF/Word/图像/文档/PPT/ZIP 样本，无外部引用 | 首选，精选约 15–25 个类型资产 |
| Microsoft Fluent UI System Icons | MIT，另有 NOTICE；有 Color 资产，风格适合 Windows，但通用图标多于具体扩展名 | 备选，适合通用文档/文件夹等 |
| vscode-icons | 源码 MIT；README 明确图标 CC BY-SA，品牌图标另有版权条款 | 本轮不选，不能把代码 MIT 等同于图标 MIT |

首选固定来源：`material-extensions/vscode-material-icon-theme`，提交 `f368264282ef14ee7feb012fd54e825181eff9c3`。落地前保留所选资产、版权/MIT 文本、来源清单；品牌标识只用于识别文件类型，不暗示合作或授权关系。

建议映射：PDF 红、Word/文档蓝、Excel/表格绿、PPT 橙、图片青绿、视频紫、音频暖色、压缩包黄、代码/配置按统一色系，未知类型使用中性文件图标。优先使用不强调品牌的通用文件图形。

显示尺寸统一为 24–28px；主页面和浮窗复用一个安全的扩展名映射。支持大小写、无后缀和复合后缀。图标随安装包离线提供，不能每一行都请求远端资源或调用 Shell 提取图标。深色主题采用合适的浅色变体或柔和底托，不整体反色；选择状态、类型文本及无障碍名称不能只依赖颜色。

搜索、排序、关闭等操作按钮继续复用现有 Lucide 图标，仅按状态适量着色，不在同一界面混用多套操作图标。

## 7. 实施顺序与验收

| 工作包 | 交付与退出条件 |
| --- | --- |
| P0 原生闪现定位和修复 | 先复现菜单后收起，记录中间帧；修复后连续 100 轮通过，回归焦点、透明间隙和截图恢复 |
| P1 自动范围策略 | 发现磁盘、固定排除、卷身份、权限与云盘边界；普通/加速/增量/缓存规则一致 |
| P2 一次引导与服务生命周期 | 首次授权、重复进入、取消、修复、服务兼容升级；主程序保持普通权限，退出后停止 |
| P3 简化页面和图标 | 隐藏两配置模块、居中引导、无底线搜索框、精选彩色资产、双主题与中英文 |
| P4 全盘行为与性能 | 多盘单盘失败、热插拔、在线映射盘/断网、云占位、百万规模、取消与退出；结果覆盖和内存有实测证据 |
| P5 联合回归 | 当前架构/构建/安全/CLI/Rust 门禁；现有记录模式/截图/搜索入口兼容，文档和更新日志同步，再按用户指令打包 |

重点用例：旧用户迁移只做一次；UAC 取消不循环；首次索引途中仍可搜索；退出重启无需反复授权；排除目录移入/移出能收敛；同名普通目录不误伤；访问不了的盘不拖住其他盘；下拉菜单未选项/选项后再折叠均不闪原生框；100%/125%/150%/200% 缩放、减少动态效果和不同主题均验证。实体多屏、其他 Windows/显卡环境需真实设备覆盖，不以几何单测替代。
