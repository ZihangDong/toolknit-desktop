# V3.3 文件快速搜索：产品、交互与实施规划

日期：2026-11-03。状态：用户已批准，实施与验收进行中，进度见 [实施记录](V33_FILE_SEARCH_IMPLEMENTATION.zh-CN.md)。本文以用户最后确认的「工具页 + 胶囊悬浮窗」为准，替代前期系统任务栏嵌入方案。

## 1. 最终产品边界

一个搜索引擎、两个入口。工具页用于集中查找，桌面胶囊用于临时查找。共同支持实时输入、文件后缀筛选、排序；每个结果只有一个操作：**在系统资源管理器中打开所在文件夹并选中这个文件**。

不自动执行文件。单击行选中，双击行不启动文件；文件行不提供额外右键菜单。键盘 Enter 在明确选中结果时执行同一定位动作。首次没有自动选中项，中文组词期间 Enter 只确认输入法。

当前范围为文件名/路径检索，首版结果仅列文件。文件夹作为搜索范围和路径条件，不混入文件结果；文件正文、AI 语义搜索、删除、重命名、批量操作、文件预览不进入本轮。这个收敛避免把快速定位做成第二个资源管理器。

### 用户要求逐项落点

| 已确认要求 | 方案 |

| 不再嵌入系统任务栏 | 与任务栏方向无绑定；按显示器工作区避让左/右/上/下任务栏 |

## 2. 工具页

沿用现有顶栏，主体保持清楚的纵向结构：

1. 标题「文件快速搜索」，短说明；右侧「桌面胶囊」开关和收起的范围设置入口。
2. 大搜索框，左侧搜索图标，右侧有内容时出现清空按钮。复用内收底线聚焦样式，无外扩光晕。
3. 后缀筛选与排序一行；右侧显示当前搜索范围。窄窗口允许换行。
4. 结果列表：文件类型图标、文件名、父路径、大小、修改时间，最右为唯一定位按钮。
5. 底部状态显示结果数量、索引状态与覆盖范围；不把调试计数、技术术语或复杂报告常驻在页面。

默认排序为「最相关」。文件名只占一行并优先保留扩展名；父路径可中间省略，悬停/键盘聚焦定位按钮时提供完整名称与路径的可访问描述。窄布局将大小/时间移入辅助信息，不挤掉定位按钮。

工具页跟随 ToolKnit 的浅/深色主题；语言切换保留搜索状态。后台建索引不遮住整个页面，已收录的文件可立即查询。

## 3. 胶囊悬浮窗的视觉规格

以下为默认逻辑尺寸，最终通过实际字体和 100%/125%/150%/200% DPI 校准。20px 指界面逻辑像素：150% 缩放下对应 30 个物理像素，避免高 DPI 下视觉间距缩水。

| 元素 | 默认规格 |
| --- | --- |
| 收起胶囊 | 148 × 48，圆角 24，搜索图标 18，图文间距 10 |
| 展开输入框 | 约 500 × 56，圆角 28；宽度按工作区收窄 |
| 结果卡片 | 与输入框同宽，圆角 24；默认最大高度约 406 |
| 两块间距 | 可见表面边缘之间 20，始终透明 |
| 结果行 | 默认约 72 高，文件图标、名称/路径、右侧定位图标 |
| 筛选区 / 底部状态 | 固定在卡片内顶部/底部，仅中间结果滚动 |
| 距工作区边缘 | 默认至少 12，含阴影的视觉安全余量 |

悬浮窗按用户指定**保持白底、黑色正文与图标**，不因主程序深色而自动变黑；次要信息使用可读的中灰色。系统高对比度/强制颜色模式优先可访问性。工具页则正常适配双主题。

收起胶囊不加状态红点或常驻报错角标；故障在展开的结果卡片说明，避免重现历史浮窗的莫名红点。背景不使用磨砂或大面积半透明，提高不同桌面背景上的可读性。

滚动条使用细、低干扰、悬停/滚动时可见的样式，支持滚轮、触控板、键盘；本工具不继承旧历史浮窗的“仅底部横向滚动进度条”，避免隐藏大量搜索结果的可浏览性。此处属于规划选择，可在验收时调整外观。

## 4. 展开、收起与焦点

### 4.1 展开动画

- 用户单击胶囊立即有轻微按压反馈，随后 280–320ms 完成形变，使用单调缓出曲线，不明显回弹或抖动。
- 胶囊背景从原宽高过渡到输入框，保留搜索图标作为视觉锚点；文字「文件搜索」先淡出，输入框内容随后淡入。
- 结果卡片延后约 80–110ms 开始，以 160–220ms 的轻微位移/缩放与透明度进入；不用全屏闪白/闪黑。
- 在窗口和输入控件就绪后的首个可绘制帧交给用户输入，不强制等动画结束。新输入不能因动画或窗口切换丢失。
- 仅背景/容器形变；输入文字与结果文字不整体横向拉伸。结果更新不反复播放整张卡片的入场动画。

原生窗口只在展开/收起边界设置目标尺寸；中间视觉变化由前端完成，不通过每帧 IPC 改系统窗口宽度。动画取消、逆转和减少动态效果都必须有确定终态，业务不依赖 `animationend` 成功触发。

### 4.2 收起规则

- 右侧收起按钮或 Esc：恢复胶囊。输入框清空按钮只清空关键词，不收起、不重置后缀和排序。
- Esc 优先级：输入法候选 → 后缀/排序弹层 → 收起浮窗。不能让中文选词的 Esc 直接关掉窗口。
- 点击组件之外的其他应用：收起结果与输入框，保留胶囊，不抢回焦点。
- 鼠标离开不收起；在两块之间经过 20px 空隙也不收起。下方卡片、下拉菜单、输入法窗口属于同一交互会话。
- 点击定位按钮：先做受限路径校验。系统接受定位请求后收起到胶囊，让资源管理器获得前台；失败则保持展开并显示原因。不能在 `blur` 提前收起导致按钮 click 没有执行。
- 本次程序运行内保留浮窗关键词、筛选和排序；下次展开恢复。重启默认清空关键词，避免私密搜索词被长期保存；可以持久化后缀与排序偏好。
- 初始焦点仅进入输入框。空输入按 Enter 不执行首项；有选中行且不在组词时 Enter 才定位。↑↓ 移动选中行，并保持它在可视区内。

状态机为 `disabled/hidden → collapsed ↔ opening/expanded/closing`，移动状态正交处理。任何异步操作都携带窗口 generation；连点时以最后一次展开/收起意图为准，只有一组窗口。

## 5. 拖动、屏幕边界与多屏

- 收起时整颗胶囊可拖动，位移超过约 6 个逻辑像素才视为拖动；松手不能同时触发展开。
- 展开后仅左侧图标/握持区域可拖动；输入框用于选择文字，筛选和结果区域不当拖动区。
- 展开状态按一组移动，两块窗口保持宽度、间距及相对方向。每帧最多合并一次位置更新，原生主线程应用，避免两块追赶。
- 位置以显示器工作区为边界，任务栏在左侧也会自动避让，不依赖底部任务栏假设。
- 默认结果在输入框下方。下方不够容纳最小结果卡片，而上方更宽裕时，整体放到上方，间距仍为 20。方向在一次展开期间稳定，普通结果刷新不来回翻转。
- 左右根据胶囊锚点选择稳定的展开边，尽量保留胶囊图标所在侧；约束后的展开位置与收起锚点分别保存，收起回原锚点，不积累位移。
- 拖到边界后松手，用约 180–220ms 缓出回到工作区内；用户重新按住时立即取消回弹。
- 跨屏拖动以胶囊中心确定显示器；松手确认新 DPI、重新计算逻辑布局。屏幕断开、分辨率变化、睡眠恢复时，将锚点映射到最近可用显示器，保证仍可见。
- 保存显示器标识、相对工作区位置与 DPI；不只存绝对像素。屏幕过小时优先缩窄卡片和减少可见行数，随后内部滚动，不用整体缩放把文字变得难读。

## 6. 20px 真透明：原生窗口方案

推荐使用两个配对的无边框 WebView：

- **A 窗口**：胶囊/搜索输入框，收起时只有胶囊尺寸。
- **B 窗口**：筛选、排序和结果卡片，收起时隐藏。

两者的可交互窗口区域不跨越 20px 间隙，间隙不是白底父容器或一整张透明大窗口。阴影优先使用已有穿透阴影路径；不能为了阴影扩出一个截获鼠标的隐形矩形。CSS `pointer-events:none` 只影响网页内部，不证明点击能穿过原生窗口到其他应用。

初期原生验证必须检查间隙上的屏幕命中目标：点击会到达底层桌面/应用，悬停滚动不被截获。透明圆角外围也要检查。若单纯窗口裁剪影响阴影，使用独立不激活、忽略鼠标的阴影表面，不扩大交互矩形。

两窗共享一份原生会话和 geometry revision；按配对显示/隐藏/置顶顺序执行。点击 B 导致 A 失焦时，通过前台窗口归属判断是否仍在会话内，不能直接监听 A 的 blur 就收起全部。下拉尽量在 B 内渲染，输入法组词状态和候选窗口归属单独验证。

应用只注册一组浮窗实例。A/B 的失败恢复必须原子化：一块创建失败时撤回另一块，保留设置并提供重试。收起、停用浮窗、退出应用和 WebView 崩溃均遵守 generation 防止旧任务重新显示；正常离开工具页不关闭已启用的桌面胶囊。

已有记录浮窗的一窗膨胀动画适合当时的球→面板；此处形状和透明间距不同，复用其基础能力即可，不直接复制整份 history controller。

## 7. 实时搜索、后缀与排序

### 7.1 输入规则

- 普通输入约 100–120ms 合并一次；新输入发生时立即使旧查询失效，不能等防抖结束才失效。
- 中文 composition 期间暂不提交查询；compositionend 后统一搜索。清空、切换后缀和排序立即生效。
- 文件名优先匹配，允许路径关键词；空格多词为 AND，保留必要的引号字面量能力。高级正则/命令语法不作为首发界面入口。
- 支持中文直搜、ASCII 大小写不敏感、拼音全拼/首字母/混合音节。生僻字/多音字覆盖以实际词典为准，保留字面匹配兜底。
- 关键词为空且无后缀筛选时显示简洁空态，不默认把所有私人文件铺满。只选后缀时可以浏览该类型；只改排序仍保持空态。
- 每次查询有 `viewId + queryRevision + scopeRevision + indexGeneration`。迟到结果只允许更新对应入口的当前会话。

### 7.2 后缀筛选

统一提供「全部后缀」、常用后缀、当前索引可用后缀和「无后缀」，允许在筛选弹层内查找后缀。首版单选，默认全部；后缀与关键词按 AND。按钮显示当前后缀，选项再多也不挤宽搜索框。多后缀组合不作为本版交付前提。

后缀统一去掉前导点、ASCII 转小写，重复项去重；`.PDF` 与 `pdf` 同一项。首版按文件名最后一段后缀识别，`archive.tar.gz` 归 `gz`，`.gitignore` 等单前导点无其他分隔的文件按无后缀处理。不要按媒体 MIME 猜测后缀。

筛选列表与数量基于当前完整检索范围，而不是当前加载的前 50 条。索引未完成时不显示伪精确的“全部文件数”。用户筛选出空结果时保留选项并解释，不自动替用户清掉。

### 7.3 排序

默认最相关，另外提供名称 A–Z / Z–A、修改时间最新 / 最早、大小从大到小 / 从小到大。默认最相关依次考虑完整名、名字前缀、多词/拼音、路径等信号；最终同分用稳定标识排序。

时间或大小未知的条目统一放后，不能显示成 0 字节或 1970 年。用户指定名称/时间/大小排序后严格按该字段，不继续把程序类型偷偷提到前面。名称采用一致、可测试的自然排序口径，中英文设备不随意改变结果顺序。

结果分页与稳定快照关联，切换筛选/排序重置游标和滚动；正常增量刷新按稳定 ID 保留选中。用户导航过程中不把新文件突然插到鼠标下；状态提示有更新，可在空闲时应用。分页失效重新查询并解释，不重复拼接旧页面。

## 8. 单一文件定位操作

行尾固定文件夹定位图标，悬停提示「打开所在位置」。Tab 可聚焦按钮；完整文件名放入 aria-label。每行只有这个按钮，状态反馈不变成另一排操作。

原生动作接收查询会话中的受限结果 ID，再取对应路径；前端不能把任意路径/命令拼进接口。验证请求属于当前用户、仍是允许范围内的已知条目，并检查父目录/文件是否存在。

Windows 优先通过 Shell 的 PIDL / `SHOpenFolderAndSelectItems` 等方式定位，避免拼接命令或错误解析带逗号、空格的路径。特别覆盖中文、长路径、UNC、快捷方式及符号链接：定位**用户看到的目录项**，不解析 `.lnk` 并启动目标，也不默认选中符号链接所指向的文件。

现有 `native_runtime/office/files.rs::open_path` 已对普通文件使用 Explorer `/select,`，但会 canonicalize 路径；目录又是直接打开目录而非选中目录项。因此可复用已有错误/打开位置服务边界，不能把所有搜索结果无区别塞进去就宣布完成。需要在平台层补一个语义明确的定位适配，保持旧转换工具命令兼容。

文件已移动/删除：保留当前查询，提示原地址已失效并触发索引校正；不打开一个不相关文件。无权限、离线盘、网络不可达分别提示。单行定位期间短暂禁用该按钮防止连开窗口，其他结果可正常浏览。系统 API 接受请求与资源管理器真实选中结果分别验证；程序不承诺能够绕过 Windows 的前台焦点策略。

## 9. 索引与原生引擎

### 9.1 选型和模块边界

以已审查的 Win顺 MIT 模块作为主要候选，遵循[复用审查报告](V33_WINSHUN_REUSE_AUDIT_20261103.zh-CN.md)。保留适用的 C++ 匹配/拼音/NTFS 部分；Qt 的字符串、存储、任务通知与编排适配到 Rust/项目已有能力。无需安装 Everything 或 Win顺主程序。

核心独立于两种界面，索引只建一份。搜索与索引维护线程隔离，界面只拿有限摘要和分页结果。保留类型化状态、取消、预算和故障隔离，不把索引塞进 JS 或每次输入启动一个进程。

初始以用户权限搜索 worker 为服务边界；原始卷读取通过可选、最小职责的高权限 NTFS 服务。服务只开放必要元数据接口，不照搬 Win顺的 UIAccess、输入监听、剪贴板与全文内容读取。服务名称、管道、配置、缓存和安装项与 Win顺隔离，互不覆盖。

服务 IPC 必须绑定已授权用户身份，校验会话、消息长度、卷与范围；不能向任意本机进程开放全盘元数据。返回结果执行范围和访问策略过滤，缓存设置当前用户 ACL。Rust/C++ 边界明确缓冲区长度、所有权、错误码与异常隔离，保留上游 SIMD 读取所需尾部空间等约束，不用裸指针跨异步生命周期。

### 9.2 首次使用

首次打开工具页用简短的页内准备区选择范围：常用位置预选桌面、文档、下载，用户可增减，点击「建立索引」后立即开始。准备区不会阻止用户查看功能说明；索引开始后可边建边查，显示真实收录数而非虚构百分比。

「全盘加速」是额外选择：说明它为所选 NTFS 卷建立文件名/路径等元数据索引，并提示安装服务需要一次管理员授权。授权取消、服务受策略限制或卷不支持时仍可普通目录模式运行。全盘元数据索引可能包含其他用户目录中的文件名，不能宣称只要文件内容无法读取就没有元数据可见性问题；范围选择与本机缓存权限要明确。

胶囊默认关闭。用户在工具页开启后显示；尚未配置索引时，展开提供简短状态和进入工具页配置入口，该入口属于空态引导，不是文件行的额外动作。

### 9.3 缓存、更新与资源

- 元数据/缓存保存在当前用户应用数据目录，不上传；查询词只保留本次进程会话。缓存与持久选项版本化，损坏重建不影响原文件。
- NTFS 使用 MFT 首次建立、USN 追增量；普通目录使用受限并发遍历 + 变化监听 + 漏事件重扫。停机期间日志有效则补变化，否则重扫，不能把过期索引标为全部就绪。
- 检测 USN 状态必须只读。上游查询函数可能自动创建日志，这部分不能原样复用；缺少日志时降级并说明，只有明确的加速设置流程才能执行系统变更。
- 分盘保存覆盖范围、卷序列号、索引状态及日志位置。盘符复用、离线与重连不能把旧盘缓存误认新盘。
- 不自动扫描网络共享、不下载云占位文件内容、不跟随重解析点无限递归。用户明确添加的远程目录需要有界扫描、取消、超时和离线状态；不能让同步网络 I/O 拖住取消或退出。实施采用普通权限独立工作进程隔离远程访问，并以超时、取消和 Windows Job 管理生命周期；验证范围见实施记录。
- 删除索引只清缓存。服务不可用时仅搜索仍明确有效的已存索引/普通范围；过期条目必须标记，不能把缺失范围伪装成“无结果”。
- 后台维护属于应用级 owner。关闭工具页取消该页面查询；已开启胶囊或其他入口仍可使用引擎。用户于 2026-11-03 确认：托盘运行继续更新，完全退出则取消任务、保存快照、释放句柄并停止索引服务工作；下次启动校验日志并补齐变化。服务使用客户端租约/断连回收，不能仅依赖正常退出消息。
- 索引首扫和搜索线程预算需与截图、录音、转写协调；交互查询优先于首扫。收起后停止动画和结果刷新，继续轻量增量维护；不得为了降低任务管理器工作集而频繁清内存造成下一次打开卡顿。

两个入口共享索引范围和浮窗开关；各自拥有关键词、后缀、排序、分页、滚动、选中项与 query revision。通过浮窗菜单「打开工具页」主动交接当前查询；普通从首页打开保持工具页自身状态，不强行同步另一处输入。

## 10. 与现有记录悬浮窗的复用

| 现有入口 | 可以复用的内容 | 不能直接沿用的内容 |
| --- | --- | --- |
| `quick-screenshot/history-window.js` | 展开/收起的 generation、拖动阈值、IME、防抖、释放模式 | 剪贴板服务、历史/常用语模式、20 条上限、复制/备注/删除动作 |
| `history_actions.rs` / `mod.rs` 几何函数 | 工作区夹紧、多屏选择、拖动回退、固定目标窗口尺寸 | 96×96 球、376×760 历史面板尺寸、截图域状态 |
| `history_menu` / `shared/context-menu.js` | 圆角自绘菜单、token、失焦/点击顺序 | 文件行额外动作，以及绑定截图偏好的命令 |
| `platform/window_visibility.rs` | 真实 HWND 与框架可见性一致，避免 hide 无效 | 不另写仅调用前端 hidden 的关窗方式 |
| `platform/window_shadow/` | 独立不激活、穿透阴影的现有机制 | 不默认认为 CSS 透明就具备跨应用鼠标穿透 |
| `app/auxiliary-tool-navigation.js` | 唤起主窗、退出当前 overlay 并打开目标工具 | 不只切换路由却忘记恢复隐藏主窗 |
| `native_runtime/office/files.rs` | 既有定位边界与普通文件行为 | 对快捷方式/符号链接的 canonicalize 语义需明确 |

新增 `features/file-search/`、平台 adapter、原生 `file_search/` 及小范围共享辅助窗几何/可见性组件；需要真正跨工具的部分再提取。不能把新业务追加到截图 controller 或 application-runtime。

截图启动时，新搜索窗也应临时隐藏并按用户意图恢复。现有截图隐藏逻辑主要识别主窗和 `screenshot-*` 前缀，新增窗口需要纳入统一受控辅助窗口登记；不能靠假装取截图前缀混入命令权限。截图期间用户关闭浮窗，结束后不能擅自恢复。

不修改现有“一键记录模式”的开关含义，文件搜索不跟着它自动启用。浮窗的右键菜单仅管理入口：打开文件搜索工具、隐藏到下次重启 ToolKnit、关闭桌面胶囊。隐藏是本次运行状态，关闭是持久设置；工具页开关立即生效。该菜单不应用到文件结果行。

## 11. 异常与可访问性

| 状态 | 用户看到什么 | 系统行为 |
| --- | --- | --- |
| 未建立索引 | 简短准备说明/进入工具页设置 | 不谎报“找不到文件” |
| 正在建立索引 | 可搜索已收录文件，标明构建中 | 取消/关闭 UI 不丢最后有效快照 |
| 查询中 | 小型就地状态，控件可用 | 新查询取消旧任务；旧行在新查询期间不得误操作 |
| 无匹配 | 保留关键词/后缀并给出短提示 | 不自动改范围或上传 AI |
| 卷离线/服务失联 | 标明哪部分不可用 | 有界重试，恢复后重新校验 |
| 文件定位失败 | 当前卡片内短提示 | 不收起、不执行文件、不循环重试 |
| 某个浮窗创建失败 | 单一可理解错误，胶囊可重试 | 隐藏半成品窗口，清理监听与状态 |
| 程序升级/缓存损坏 | 提示重新整理索引 | 保留设置，原文件不动 |

键盘覆盖 Tab、Shift+Tab、↑↓、Home/End、PageUp/PageDown、Enter、Escape；控件具备明确名称。结果总数用节制的 aria-live，不逐个读出每次动画或输入变化。长文字不压缩字体解决溢出；高 DPI、触控目标和减少动画模式单独检查。

不默认抢占系统快捷键。可在设置提供自定义唤起/聚焦组合，默认未设置；冲突只影响快捷入口，不能阻断工具页和胶囊开关。

## 13. 验收标准

### 必须全部通过的行为

1. 工具页与悬浮窗均能实时搜索、筛后缀、切排序；无手动搜索按钮。
2. 每个结果恰好一个定位图标；点击/Enter 在资源管理器选中文件，无文件启动、无额外右键动作。
3. 胶囊保持白底黑字；形变连续，输入不被横向拉伸，连续展开收起 50 次无卡死或重复窗口。
4. 可见表面间隙是 20 逻辑像素；真实 Windows 上间隙可点击底层应用，透明外围无黑底。
5. 点击结果、下拉、输入法候选不会误收起；点击外部按规则收起且不抢焦点。
6. 拖动阈值、边缘回弹、屏幕变更、任务栏四边、多显示器负坐标和不同 DPI 无越界。
7. 快速输入、切筛选、分页、切工具、关闭/重开均不显示迟到的旧结果；中文组词不误搜索或误定位。
8. 索引未完成/受限/离线时状态真实；目录改名、文件移动/删除与快照恢复收敛，原文件不受影响。
9. 隐藏到重启、永久关闭和再次启用立即生效；一键记录开关不受影响。
10. 截图与本工具同时开启，隐藏/恢复顺序正确，取消截图不留下黑块或抢焦点窗口。

### 性能目标（尚未实测）

参考：Windows 10/11、4–6 核 CPU、16GB 内存、SSD；另外用 8GB/机械盘作为兼容组，分别报告。

## 14. 本轮规划验证与最终自查

已经核对实际项目中的历史窗口展开/收起、窗口主线程可见性、工作区夹紧、菜单 token、辅助导航、路径定位实现，并与 Win顺复用审查衔接。已制作可交互的两入口效果示意，使用合成文件数据，按钮只展示定位反馈。

原型检查：已验证宽布局、400px 与 320px 窄布局，展开表面等宽且间距为 20px；关键词「合同」显示 5 条、DOCX 筛选后 2 条、大小排序、无匹配状态、Esc 收起以及两个入口查询隔离。修正了最窄布局的固定最小宽度导致按钮裁剪；检查期间控制台没有警告或错误。原型只展示主要路径，不能替代中文系统输入法、原生窗口命中、多屏拖动或实际索引性能测试。

规划自查消除了以下冲突：

- 20px 透明与全窗口鼠标遮挡：采用配对窗口，并以原生命中验证为门槛。
- 收起与中文输入/点击筛选冲突：用窗口会话归属和分层 Escape，不直接绑定单窗 blur。
- 两入口共享与相互打断：只共享索引与范围，查询状态按入口隔离。
- 默认白色浮窗与深色界面：浮窗遵循用户指定白色，工具页正常双主题。
- 已有定位代码与搜索条目语义：单独校验快捷方式/链接，避免 canonicalize 误选目标。
- 展开位置与拖动锚点：分别存储，不让反复开关漂移。
- 搜索器与一键记录/截图：独立开关与数据，只有受控辅助窗口基础设施共享。
- 功能完备与范围膨胀：每行仅定位，不混入文件管理、正文搜索或 AI。

方案可以进入实施评审。这里的完成指产品决策、架构责任、失败路径与验收要求已闭合；原生效果和性能仍必须在实现后验证，不能将规划满意度当作测试结果。
