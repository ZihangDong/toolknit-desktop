# V3.3 截图取消与速度专项

日期：2026-11-15。3.3.0 开发中；本轮以用户反馈的“快捷键框选后按 Esc，遮罩仍留着”为入口。

## 定位与修正

1. 原来的 Esc 会依次取消处理、回退拖动、取消组件选择、清空选区，最后才退出。现改为画布内一次 Esc 直接取消截图；文字弹框、下拉菜单先关闭自身。正常框选、拖动和处理中的取消均释放任务、鼠标捕获及像素资源。
2. 图片 IPC、浏览器解码和启动队列缺少截止与取消，旧请求不返回时会挡住后续截图。`capture-source.js` 为每阶段提供取消和 8 秒截止；结束或新会话立即中止旧启动。元数据尚未返回时，也使用打开通知中的编号取消原生会话。
3. 结束通知原来不携带会话编号，迟到通知可能清掉新的界面。`screenshot-ended` 现在携带编号或 null；前端丢弃旧编号，兼容旧空载荷。原生开始新截图前等待旧窗口清理结束，并设置有界等待。退出标志在状态锁内核验会话后取得，避免旧超时占住标志、跳过当前取消。
4. 原生 starting/work 标志改用作用域释放，避免异常或取消遗留忙状态。系统捕获最多等待 6 秒，同时保留单 worker 名额，直到真实 OS 调用返回。显示窗口前释放状态锁，显示后再核验会话。
5. 悬停取色原先每次 pointermove 采样并读写布局，绘制还会重复刷新按钮、下拉状态。现每帧合并采样/绘制、缓存控件状态及画布边界；整屏取色副本按需创建，提前就绪阶段不再强制复制整屏。
6. 取消失败时恢复可操作状态，避免已经中止任务却继续保留处理遮罩。独立“取消处理”入口保留，Esc 负责结束截图。
7. 隐藏界面用合成的 1×1 PNG 预热图片解码器，不读取桌面像素；等待支持取消并限制在 1.5 秒内，失败不阻断正常截图。

## 测量口径

- 先测现有版本，再在同一机器以 release 优化模式比较。真实取屏只保留内存像素，不保存桌面图片，不上传。
- WebView 基准用固定 1080p/4K 合成图、真实 WebView2 和隐藏窗口；图像编码已缓存，因此它测的是会话、传输、解码与编辑器就绪，不等于真实快捷键到屏幕可见帧的完整耗时。
- 比较过 RGB 压缩：合成 4K 图片从约 7.7 MB 减至 6.7 MB，但编码中位数约从 45 ms 增至 49 ms，因此未采用。最终保留无损、四字节对齐的 PNG，并尽早释放 GDI 对象。

## 验证与性能

同机隔离 WebView2 基准，单位毫秒。下表为基线与最终退出并发修正后的复测；解码预热三轮 4K 中位数为 61.89–63.09 ms，较基线约减少 17%–19%。1080p 基本持平，首次/冷重建仅各一例，不能作稳定性能承诺。

| 场景 | 次数 | 基线中位数 / P95 | 最终中位数 / P95 |
| --- | ---: | ---: | ---: |
| 已预热首次打开 | 1 | 52.06 / 52.06 | 47.56 / 47.56 |
| 1080p 重复打开 | 69 | 30.45 / 31.47 | 30.94 / 31.56 |
| 4K 重复打开 | 30 | 76.07 / 78.08 | 61.89 / 63.52 |
| 销毁后冷重建 | 1 | 186.32 / 186.32 | 170.69 / 170.69 |

真实桌面捕获另测各 10 次：1920×1080 中位数 29.59 → 28.57 ms，最大值 32.18 → 35.27 ms。前后桌面内容和编码大小不同，不认定为显著提速，也不把它与 WebView 数据拼成完整延迟。

## 边界

操作系统捕获调用无法在进程内安全地强杀。若驱动调用超时，会返回错误并保留单 worker 名额，防止重试堆积；必须等该调用返回后才能再次取屏。硬件、显示器和桌面内容会影响耗时；本机隔离基准不能保证所有设备的固定速度。
