# V3.3 PDF 大文件修复记录

日期：2026-10-28。状态：V3.3 未发布开发修复。使用用户授权的本地 44 页、42,398,531 字节 PDF 进行验证；原件、文件正文、截图与结果不进入仓库，不上传网络服务。

## 问题与证据

旧代码逐页调用 `PDFDocument.copyPages`，每次重新创建资源复制器。测试样本包含共享资源和大量页面级 `PieceInfo` 原设计软件私有编辑数据。44 页逐页复制后，流内容由 42,344,155 字节膨胀至 454,588,059 字节，间接对象达到 6,942 个。原来的桌面写出还使用 `Array.from(bytes)` 再 JSON 序列化，进一步扩大内存压力。

编辑器保留完整原序页面时走原位保存；删页或重排后走逐页复制。因此同一文件可能完整保存正常，删页后失败。拆分合并、独立页 ZIP 和其他页面派生工具也受资源复制影响。没有取得用户旧版桌面的完整 RangeError 堆栈，不把 `INVALID ARRAY LENGTH` 唯一归因于某一个底层函数；本轮同时修复已证实的资源膨胀与 JSON 传输问题。

切页时主预览与缩略图原先各自调用 `PDFPageProxy.cleanup()`，容易重复解码；主画布也没有最近页面缓存。本轮增加解码页面租约和有界画布缓存，保留原有异步版本隔离。正在预览的页面与被勾选的页面分开显示和操作。

## 实现边界

| 文件/模块 | 职责 |
| --- | --- |
| `src/core/pdf-page-copy.js` | 每个目标/来源复用 copier；共享流仅复制一次；页面内容数组和资源字典独立，避免重复页的后续编辑串页；派生页去除 PieceInfo，原件不修改 |
| `src/pdf-{editor,merge,split,rotate,page-number}-core.js`、`features/pdf-crop/core.js` | 各工具沿用原有页面顺序、旋转、表单外观与取消契约，接入共享复制 |
| `features/pdf-{split,rotate}/workbench-export.js` | 工作台和 Worker 输出也使用同一复制逻辑 |
| `src/shared/pdf-page-retention.js`、编辑器 documents/thumbnails/preview | 默认保留 6 个解码页，活动租约不被提前清理；3 张/1,600 万像素画布上限；关闭重置释放，旧任务不污染新结果 |
| 编辑器 file-session/selection/controls/exporter/content-editing | 导入全选、切页不改勾选、按文档顺序导出所选页、空选禁用、部分导出保持未保存保护；文字弹框关闭前复用安全焦点处理 |
| `src/platform/binary-output.js`、Rust `native_runtime/media/io.rs` | 原始 Uint8Array 传输；512 MiB 上限；路径元数据头大小限制；阻塞线程执行既有唯一名称写盘 |
| 六个 PDF exporter | 编辑、拆分、合并、旋转、裁剪、添加页码使用二进制保存；浏览器下载不变 |
| `scripts/stage-cli-resources.cjs` | CLI/MCP 独立包包含共享复制模块，避免仅开发目录可运行 |

新增 Tauri 命令 `write_unique_file_binary`；旧 `write_unique_file_bytes` 保留。主预览画布通过内部 `data-page-id` 标识已提交页面，便于核对快速切页结果；新渲染排队期间旧页结果也会失效。没有更改已有 DOM ID、存储键、事件、CLI/MCP 参数、用户设置、模型或历史记录。当前 Tauri 155 个实现、154 个独立名称。

## 真实文件结果

| 场景 | 输出验证 | 大小（字节） |
| --- | --- | ---: |
| 删除 3 页后导出 | 41 页 | 29,908,297 |
| 重排与重复页面 | 顺序及重复的 4 页正确 | 1,477,684 |
| 删除后插入形状 | 41 页，编辑链路成功 | 29,908,640 |
| 拆分当前第 21 页 | 单页 PDF | 1,242,524 |
| 拆分全部合并 | 44 页 PDF | 32,698,546 |
| 拆分独立页 ZIP | 44 个可打开单页 PDF | 32,923,921 |

使用 PDF.js 和 Canvas 按宽 700 像素渲染，对删页结果、重排重复页、单页、44 页合并与 ZIP 每页做了 **134 次精确像素哈希对比，全部相同**。这验证本样本在该渲染尺度下的可见内容一致，不等于承诺任意 PDF、任意阅读器或任意倍率绝对一致。原件 SHA-256 前后相同。

真实浏览器工作台在白天/深色两种主题下完成 12 次下载：编辑器默认 44 页、所选 3 页、删除后 41 页；拆分当前页、44 页合并、44 项 ZIP。另验证空选禁用、普通切页不改变勾选、删除撤销、返回与重开清空会话；未出现未捕获页面异常。UI 测试删除的页码与 core 用例不同，输出大小不同是预期。

## 性能与覆盖限制

最终 Edge 测试按画布 `data-page-id` 确认目标页已提交：导入约 515ms；最近页面重复切换为 40–77ms。首次访问未解码的第 21 页约 2.54 秒，回访为 54ms。测试过程中冷页耗时有波动，不把缓存命中速度宣传为所有页面首次打开速度，也不承诺固定帧率。早期基线仅观察画布替换，测量口径不同，不据此声称精确提升百分比。

保留 PDF 中可见的图像/文本/外观，不栅格化整个文档。去掉的仅为派生页的设计软件私有编辑附加数据，因此派生 PDF 不保证还可在原设计软件中恢复全部工程信息。原文件不受影响。交互表单外观仍走既有 flatten 流程；签名、完整标签树、书签重映射等并非本次新增保证。

二进制保存已进行 JS 原始 body/中文元数据契约验证和 Windows Rust 唯一名称/路径校验/实际落盘测试；浏览器端真实下载不等于安装包 WebView2 的端到端验收。本轮没有制作或安装新测试包，需在后续测试包中确认实际桌面保存体验。
