# V3.2 复杂 PDF 转 Word 升级方案

> 2026-10-19 范围调整：用户确认以大众日常可用为本轮交付标准，复杂公式允许局部图像保真，不要求全部公式可编辑或所有阅读器完全一致。当前验收以 [交付收尾记录](V3_2_PDF_WORD_DELIVERY.zh-CN.md) 为准。下文保留原研发方案和历史诊断；200 条公式标注、原生公式全面兼容等研究项延后，不能标记为已经完成。

日期：2026-10-18，2026-10-19更新。用户已授权目标任务实施，验收要求至少95%还原。当前44页数学样本在桌面WPS已逐页通过视觉门槛，整体目标仍在实现和验证中，原生公式、独立回归及跨阅读器验收尚未完成。本文补充原`V3_2_PDF_TO_WORD_PLAN.zh-CN.md`，以失败样本作为升级依据，不把规划写成已实现。后续实测见[实施进展](V3_2_COMPLEX_PDF_WORD_PROGRESS.zh-CN.md)。

## 1. 结论与范围

当前引擎已具备原生PDF提取、基础段落/表格、可选AI结构建议和安全输出，但复杂文档能力尚未达到可稳定交付的水平。单份普通作业转换成功、单元测试通过，不能代替数学试卷和复杂图文的验收。此前验证覆盖偏窄，需要补足。

本次不是继续调间距。需要升级五个环节：文字几何、图形与内容归属、数学结构、混合布局、输出质量检查。保留现有PDF.js、MIT许可的docx、Worker、Tauri发布链和普通PDF成果，不重写整个应用。

纳入本轮主线：原生中文/英文数学试卷、短页题块、公式与正文同行、答案表、题图、两栏及跨页题目；同时覆盖这些底层能力共通的技术文档、表格报告和图文资料。扫描件OCR仍不纳入本轮，复杂公式不能假装已恢复数学语义。

目标是困难页面有可检验的处理策略，并明确剩余不可编辑部分。不能承诺所有PDF、所有阅读器、任意后续编辑都保持像素级一致。

## 2. 已完成诊断

### 2.1 样本基线

使用当前3.2.0本地引擎，未调用AI，未上传原稿。复用实际PDF.js适配器、scene、layout和DOCX Writer。全部44页已转换，并通过LibreOffice26.2.5.2生成243页可见结果；失败记录见本机忽略目录`tmp/pdf-word-math/`。

| 项目 | 实测 |
| --- | --- |
| 原稿 | 44页，宽456.491pt，高36.804至357.222pt |
| 短页 | 23页低于144pt，其中6页低于72pt |
| 转换耗时 | 单次本机5.936秒，不含Office渲染 |
| 来源账本字符 | 10,905个非空白字符 |
| 可编辑字符 | 1,126，约10.3% |
| 图片内字符 | 9,779 |
| 图像区域 | 939，其中618个不带文字来源ID |
| Word结构 | 56个section、3个表格元素、0个原生数学公式 |
| 实际渲染 | 243页，碎片、孤立线条和异常空白明显 |

无文字来源ID的图像可能是合法线条/图形，不等于无用素材；问题在于缺少结构归属，不能简单删除。

### 2.2 图片化的完整数量链

在内存中为当前场景解释器加只读诊断，不改产品源码，得到：

1. 文字初始判定：1,934字符进入图像路径，其中1,919字符因变换不符合严格水平判定，15字符因局部裁剪。
2. 后绘图形相交：另有1,161字符被转为图像，累计3,095字符。
3. 矩形扩张分组：又吞入6,684个原本可编辑的字符，累计9,779字符。
4. 剩余可编辑字符1,126；与原输出统计一致。

1,850次后绘图形相交中，1,834次涉及细线对象。样本没有触发负字号、缺字形、Type3、竖排、无效Unicode、半透明/白字不确定性。不能将本次故障归因于“用户字体缺失”或“全部公式不可解析”。

多数不支持变换来自`[1, 0, 0.176, -1]`一类矩阵，即水平基线上的剪切倾斜，常见于数学斜体。当前`horizontalTransform()`要求剪切项接近零，因此将其当成复杂文字。

### 2.3 隔离变量实验

只在诊断副本中分别放宽剪切判定、跳过细线触发的文字降级，不生成交付DOCX：

| 诊断条件 | 可编辑字符 | 图像区域 |
| --- | ---: | ---: |
| 当前行为 | 1,126 | 939 |
| 仅放宽剪切判定 | 2,885 | 806 |
| 仅排除细线相交触发 | 1,232 | 951 |
| 两者同时改变 | 7,184 | 918 |

这说明条件之间存在连锁效应，而且仅恢复文字也未解决图像碎片。实验不是可上线修复：分数线、根号横线、删除线、遮盖边缘均可能有实际语义，生产实现不能一概忽略细线。

### 2.4 缺陷与证据边界

| 原因 | 证据与责任模块 | 修正要求 |
| --- | --- | --- |
| 合法剪切被整体降级 | `core/scene.js::horizontalTransform/addText`及矩阵统计 | 分解基线方向、字号、横向缩放、倾斜与镜像；仅真正不可表示部分降级 |
| 细线一相交就降级 | `scene.js`后绘图形循环，1834/1850次涉及细线 | 分类线条用途，结合绘制顺序、实际笔画/裁剪和语义归属 |
| 分组扩张卷入正文 | `scene.js`通过union矩形不断吸收区域，新增6684字符图片化 | 以连接关系和结构边界分组；裁切范围与内容所有权联合校验 |
| 同行对象被纵向堆叠 | `adapters/docx.js::flow/image`每图独占一个段落 | 建立混合行模型，让文字、公式、图像共享基线 |
| 数学结构不存在 | 当前只有段落/图像/表格/栏，未输出OMML | 引入公式AST、可编辑公式与局部图像两种明确结果 |
| 短页适配不足 | 原页最低36.804pt，Writer底边距最低20pt，普通段落/图像占位仍照搬 | 页面容量由真实内容和页尺寸计算；区分来源片段与目标纸张 |
| 连续模式仍逐源页换页 | `createWordBytes`的每页首section始终NEXT_PAGE | 先建立目标页计划，再输出section，落实跨源页连续排版 |
| 表格/分栏建立在破碎输入上 | 首部答案表没有成为原生表格；9页触发columns并增加section | 结构识别提前消费边线，区分选项、公式对齐与真实分栏 |
| 质量检查只保证归属与格式 | `validateCoverage`及ZIP/XML检查不能发现243页错版 | 增加几何、分页、对象完整性和真实阅读器验收 |
| 当前AI覆盖范围不足 | `aiPageRequest`只选顶层paragraph，角色不含math | AI处理结构区域和公式候选，不能仅重排剩余少量正文 |

仍待验证：每个图形的真实笔画与包围框误差；9个分栏候选中哪些是误判；各公式族的可可靠识别比例；WPS/Word/微信不同版本对原生公式和短纸张的支持；新方案在独立样本上的泛化与资源成本。上述主链路有充分证据，不能据此声称所有PDF问题均已穷尽。

## 3. 支持策略

| 内容 | 主策略 | 无法可靠识别时 |
| --- | --- | --- |
| 普通正文、标题、题号、选项 | 可编辑Paragraph/TextRun | 标注编码/字体风险，局部保留原貌 |
| 分式、根式、上下标、函数、集合与区间 | 自研结构推断，生成OMML | 整个公式作为一个有基线的图像，不拆符号 |
| 矩阵、分段函数、联立式、求和积分 | 独立公式族验证后开放原生结构 | 整个公式组保留图像，并报告不可编辑 |
| 题图、坐标系、几何图、复杂曲线 | 整体无损图像，关联题干与图注 | 保留完整可见区域；不承诺图形内每个标签可编辑 |
| 答案表与有线表格 | 原生表格，显式网格/跨度/宽度 | 表格整体降级，避免一条线生成一个段落 |
| 无线表格与复杂分栏 | 空白/对齐/阅读顺序多证据判定 | 局部固定布局或用户确认图像保留 |
| 极端自由版面 | 有限锚定的整体区域 | 明确不支持或请求用户选择区域保真；禁止自动把整本变图片并宣称成功 |

实现优先级是：可见内容正确、数学含义正确、阅读顺序正确、版面稳定，再提高可编辑比例。多个指标分别报告，不以“看起来一样”掩盖全图片，也不以“可编辑率高”掩盖公式错义。

## 4. 新管线与数据模型

```text
PDF.js可见绘制证据 + 文本/字体/裁剪/结构树候选
  -> 坐标与字形规范化
  -> 图形分类与所有权图
  -> 文字行 / 数学区域 / 表格 / 图形 / 题块
  -> 本地数学AST与布局候选
  -> 可选AI审查疑难候选
  -> 目标页计划、混合行与对象布局
  -> DOCX原生结构及明确的局部图像
  -> 内容/几何/分页估计检查
  -> 安全发布；研发与可用Office环境做真实渲染复核
```

内部IR从当前schemaVersion 1演进为2。保留sources账本，新增独立的draw/region/semantic/output标识和版本适配；旧普通文档路径可迁移，但同一输出不得混用两套单位或所有权定义。

核心节点：`GlyphRun`、`TextLine`、`InlineMath`、`InlineImage`、`Paragraph`、`Table`、`Figure`、`QuestionGroup`、`RegionGroup`、`TargetPage`。公式包含`Symbol/Row/Fraction/Radical/Script/Delimited/Matrix/Cases/NAry/Accent`等有界节点。

每个节点保存：来源ID、原页和坐标、基线/上升部/下降部、旋转剪切、绘制顺序、可见裁剪、结构证据、已校准的可信状态、处理方式及风险码。图片还保存实际裁切区域、覆盖成员、资产ID和目标基线。图形和文字均有所有者，不能只核对文字来源。

同一语义内容只输出一次。背景、分数线等结构笔画可以被一个语义节点消费；同一图片资产可复用，但每次摆放实例有独立位置。移除被消费的结构线必须同时证明所属表格/公式已完整输出。

## 5. 坐标、字体与可见性

### 5.1 规范化

- 基于CTM、文本矩阵、字体矩阵、横向缩放和textRise计算有效基线和字形位置，区分页面旋转、真实旋转、剪切斜体、负字号方向及镜像。
- 支持水平基线的有限剪切，恢复可编辑斜体；不能仅把剪切项清零。字体大小与视觉倾斜分开求，避免将剪切长度误计入字号。
- 字体元数据加入PDF.js可用的bold/italic/black/fallback/missing信息，名字仅作为证据之一。对E-BX等内部字体名建立语义回退，不原样当成目标设备已安装字体。
- 字体替换须重新测量行宽和基线；不擅自嵌入PDF内的商业字体。优先现有系统字体与已核实许可的资源，不新增强制字体下载。
- 结构树仅作候选，与可见几何和来源覆盖交叉验证，防止Tagged PDF错误标签影响输出。

### 5.2 可见性不能被放宽策略绕过

继续处理透明、白块遮盖、裁剪、重复绘制和未知蒙版。字体可恢复不等于内容可见；隐藏或被涂盖内容不能进入Word文字、AI载荷或图像原始数据。无法证明的区域基于最终可见渲染作有限降级。

新增合成夹具：剪切/旋转/负字号/横缩放/textRise组合；同一字体少数字形异常不污染后续段落；部分裁剪、隐藏文本、根号线、删除线和遮盖分别验证。

## 6. 图形分类与结构归属

当前“矩形碰到就联合扩张”的分组必须替换。先保留原始路径/子路径、描边宽度、填充、裁剪、绘制顺序，再建立局部邻接图。

1. 用空间索引寻找候选，不全页反复两两扫描。
2. 把表格线、分数线、根号横线、下划线、删除线、图形边、分隔线和遮盖区分为不同候选类型。
3. 边的依据包括真实距离、方向、基线、笔画相交、包含关系、重复模式和上级区域，不能只有AABB相交。
4. 先确定表格/公式/题图等强结构归属，再允许其关联文字。禁止跨栏、跨题号、跨大空白带无限合并。
5. 对每个候选检查矩形填充密度、包围框扩张量及无关正文吞入量；超限则拆分或升级为整体区域审查。
6. 如果局部图像裁切会带入邻居文字，重新切分区域或明确让邻居加入同一整体并取消重复输出。裁切图包含的可见内容必须与所有权一致。

部分复杂图可作为一个有边界的Figure，但不应产生数十个无意义的独立图片段落。画面保真与结构恢复的边界显式记录。

## 7. 数学识别与可编辑公式

### 7.1 本地数学推断

从符号位置和笔画关系推断，而非把字符拼成一行后猜表达式：

- 分数：横线、上下内容、覆盖宽度、左右上下文，避免把表格线当分数线。
- 根式：根号字形/路径、横线终点和被开方区域，处理根指数。
- 上下标：相对主基线偏移、字号比例和归属范围，区别脚注/题号/行间注释。
- 运算符、关系符、括号、绝对值、函数名：保留原符号及顺序，不做代数化简。
- 矩阵/分段/联立：大括号、列对齐、行组和条件列共同判定；避免与正文多栏混淆。
- 求和/积分/极限/重音：运算符及上下限、箭头或帽符的附着范围。

每个公式先产生候选AST，再做字符与结构守恒、范围覆盖、嵌套和歧义校验。自动接受门槛用标注集校准，不在计划里凭空规定“置信度0.95即正确”。无法可靠归属时保留整式图像，尤其禁止悄悄把负号、分母、指数或不等号改错。

### 7.2 输出能力已经具备依赖基础

已核对锁定的`docx@9.12.0`本机API：主入口提供MathFraction、MathRadical、MathSubScript、MathSuperScript、MathSum、MathIntegral；`docx/math`提供MathMatrix、MathEquationArray、MathCases、latexToMath等。该库提供生成能力，不负责从PDF识别数学结构。

优先由受控AST直接调用这些构件，输出原生OMML。即使采用其LaTeX转换函数，也只允许经过本地白名单校验的表达式，不直接接收模型生成的OOXML或任意命令。每种构件需独立验证Word、WPS、LibreOffice；上游API存在不等于所有阅读器显示一致。

### 7.3 图像回退必须完整且可解释

仅无法可靠解析的公式整体转为一个局部图像，保持透明/背景策略、实际高度、基线和与正文的间隔；不能把分子、横线、分母拆成三行。选择题中的公式作为选项内联对象，图形作为题块内对象。结果分别统计原生公式、图像公式和待检查公式。

## 8. 图文混排与Word布局

建立`LineBox`：每行包含文字、OMML和行内图像，以最大上升部/下降部和必要间距决定行高。先测量再决定换行，不能继续“一张图一个Paragraph”。

正文、题干和解析使用正常段落；双列/四列选项用明确宽度的原生表格；真正多栏用column/section；图题与图注形成区域；有限浮动对象只能在验证锚点、环绕和层级后使用。避免把整页变成数百文本框或嵌套表格。

公式行不能统一强制固定小行高以免分式/根号裁切。普通文字仍保持已验证的间距/关闭标记兼容策略；长公式超过栏宽时优先独立公式行或合理换行，再提供局部保真，不随意整体缩小正文。

恢复答案表时，首先由表格节点消费边线和单元格内容，表格成功输出后不再绘制这些边线图片。无线表格、矩阵、选项网格有不同语义，不共用一个未经区分的“列”判断。

## 9. 来源页与目标页分离

### 9.1 保留原页

保持原尺寸/方向和来源边界；边距按该页实际可用空间计算，不使用20pt之类统一下限。相同纸张/页眉/栏结构优先复用section与普通分页，避免不必要的连续section。

该44页样本的验收目标：在可表示该尺寸的目标阅读器中保持44个对应页面，无额外内容溢出页；若阅读器对极短纸张存在下限，明确提示尺寸适配或建议整理到A4，不静默改成243页。

### 9.2 连续整理

复用现有“连续编辑”入口，落实跨源页的题块组装，再分页到A4等选择的纸张。对短页文档在分析结果中提示此模式更适合阅读，不擅自切换用户已选模式。

题干/选项/答案/解析建立关联但默认不重排原顺序；优先不拆公式和小题图。超过一页的解析允许在自然边界拆分，不能对整题无条件keepNext导致大片空白。输出页数由目标纸张和内容决定，不强行追求44页，也不在未实际布局前承诺固定页数。

两种模式都保存`sourcePage -> region -> targetPage/position`映射，使回归能追踪内容去向。目标页数如果只是估计，界面明确标为估计。

## 10. AI辅助升级

AI在本地结构候选之后、最终布局之前处理歧义，默认本地模式仍无需Key。只在用户选择AI时经既有provider/key/request runtime发送明确区域。

- 将请求对象从“顶层段落”扩展为有ID的文字、公式候选、路径摘要、题图和布局区域，发送所需局部可见图像和相邻上下文。
- schemaVersion 2只接受有界分组、角色、阅读顺序、公式AST候选及证据引用。禁止自由改写题干、生成缺失答案或修改本地原文。
- 单独区分“根据已有符号组装公式”与“识别原本无法确定的符号”；后者必须标识AI推断、展示原式对照和待确认状态，不能混进已验证原文统计。
- 复用现有8次请求、每次30秒、总90秒、6MiB请求/256KiB响应上限，按歧义区域优先级安排，缓存键含输入摘要、区域、provider/model和schema。显示已处理/未处理区域数，不暗示检查了整本文件。
- 验证来源ID唯一、候选范围、AST深度/节点数/矩阵尺寸、符号覆盖、无交叉所有权和迟到任务隔离。不可执行模型XML、URL或代码。
- 请求失败、模型不支持图片或候选不合法时保留本地结果，允许局部图像或用户复核，不盲目重复调用全部页面。

真实模型效果需要单独授权的实际请求和留出集证据；模拟响应只验证协议与恢复，不能计入识别准确率。

## 11. 质量检查与交付规则

现有来源覆盖和原生ZIP/XML安全检查继续保留，再增加三层检查：

1. 结构检查：所有文字、图形和公式均有归属；合法共享资产与重复可见内容区分；不得出现无主人线条或被漏掉的结构笔画。
2. 布局检查：真实行/表格/图像占位、重叠、越界、公式基线、异常空白、目标页估计、源页/目标页比率和图像碎片密度。不同模式有不同基线，不能拿连续排版页数与源页一比一比较。
3. 渲染检查：研发固定渲染器对比并在指定Word/WPS实测。可选本机Office复核复用现有运行时检测；WPS安装不等于具备LibreOffice headless能力，日常转换不强制安装Office。

`docx/layout`可作为辅助估计，但其`stoppedAt`、未知字体或guess必须向质量层传播。不能把估计页数当Word实际页数，复杂公式也不能只靠一个像素相似度评分。

状态区分：检查通过、带明确局部降级完成、需要复核、无法可靠转换。严重碎片化/确定溢出应阻止默认成功发布，给出有意义的局部保真或布局调整选择；用户可明确导出诊断版，但不能悄悄把失败文档作为成功结果。结果显示正文可编辑率、原生/图片公式数量、风险区域和源页数量；只有真实渲染才显示已验证目标页数。

## 12. 模块落位与兼容

所有业务仍在`src/features/pdf-to-word/`内部。建议按实现阶段形成以下边界，不预先创建空壳：

| 边界 | 职责 |
| --- | --- |
| `adapters/pdfjs.js` | 同版本操作/字体/标签证据，最终可见渲染 |
| `core/scene.js`及`scene/geometry/visibility`子模块 | 分解当前解释器的几何和可见性，不改外部入口名称 |
| `core/regions.js` | 图形分类、邻接、所有权和区域分组 |
| `core/math/*` | 符号候选、AST、验证、公式族规则 |
| `core/layout.js`、`core/page-plan.js` | 混合行、题块、表格/栏、目标页计划 |
| `adapters/docx.js`与`adapters/docx-*` | 文本、OMML、图片、表格输出及测量 |
| `core/quality.js` | 来源/结构/布局检查和风险报告 |
| `core/ai.js`、`processor.js` | schema 2有界增强与预算 |
| `controller/template/CSS/locales` | 现有入口、布局选择、问题定位与双语结果 |

保留`pdf-to-word`、`pdfWordOverlay`、初始化器和原有五个Tauri写入命令。新增UI节点/事件仅在确有需求时列清单并补契约，不将业务塞进application-runtime。

OMML仍是普通受限XML，先通过现有原生校验器的实际样本测试；若需调整安全校验，只允许明确的公式/图形结构，不开放外部关系、宏、OLE或远程图片。内部Worker协议版本随IR升级，旧会话关闭时仍需失效revision和释放全部资产。

## 13. 性能、依赖与安全

- 无新增强制Python、GPU、本地模型或云转换依赖。继续PDF.js Apache-2.0 + docx MIT；不引入PyMuPDF/AGPL运行时。复杂公式生成模块按需加载，实际包体增量构建后测量。
- 图形分组采用空间索引、受限候选边和有界连接分量，避免当前扩张循环的潜在高阶复杂度；对巨型组、超多路径、AST深度设置可取消的工作预算。
- 延续64MiB输入/输出、100所选页、32MiB资产、512MiB估计工作集边界。新增数学/区域节点计入预算；不能提高容量上限来掩盖碎片化。初始AST深度不超过32、单式节点不超过4096、矩阵不超过64行/16列，超限局部降级；最终数值须经实际样本和攻击夹具验证。
- 按页提取，保留紧凑文档级结构，逐区域生成/复用资产；原页Canvas和中间缓存及时释放。取消检查进入图搜索、公式分析和打包之前，禁止大量不可中断循环。
- 性能目标：当前开发机该44页样本离线转换P95争取15秒内，重复至少10次后报告；8GiB参考机另测。目标不是已达标结论，不把Office渲染或网络AI时间藏到统计之外。
- 不复制/提交私人原稿、截图、正文或字体；公开回归使用自制/许可清晰的近似夹具，私有样本只记录匿名指标和本地证据位置。

## 14. 验收集与阻断标准

### 14.1 样本和真值

在原方案40份/至少200页、30份开发+10份冻结留出的要求上补齐数学样本；原方案此项尚未达成，不能用自制的一套模板凑数。数学原生PDF至少覆盖3个独立制作来源和不少于200个标注公式，留出集不用于调阈值。

先标注正文、公式、图形、表格、阅读顺序与源符号，再开发。普通正文和数学公式分别统计，禁止把识别失败的正文改标成“复杂公式”以提高成绩。两个用户样本加入本地回归，但不充当泛化证明。

### 14.2 必须通过

| 范围 | 验收要求 |
| --- | --- |
| 已有6页逻辑作业 | 在指定渲染环境保持6页、3106字符归页一致、页眉和选项正常；字体/间距压力测试不退化 |
| 44页数学样本 | 无孤立碎线、重复制图、内容截断和异常空白页；原页模式匹配来源页或明确尺寸适配；A4整理按题块连续输出 |
| 正文可编辑性 | 标注为可可靠提取的普通正文至少95%输出可编辑文字；同时公开全内容比例和每类降级数 |
| 支持公式族 | 留出集原生重建覆盖率目标至少90%；任何自动接受的公式出现符号/分子分母/上下标错义，作为该轮阻断项修正，不能靠平均分掩盖 |
| 图像公式 | 每个整体公式/公式组最多一个合理图像对象；清晰、无邻居重影、不增加隐藏文字，明确不可编辑 |
| 表格/图形 | 首部答案表网格/答案完整；图形和标签同属完整题图；结构线消费后不重复输出 |
| 结构与安全 | 所有来源和绘制区域均有归属，无可见内容静默丢失；隐藏/遮盖文本不泄漏，AI不改写原文 |
| 检测能力 | 243页爆炸、严重重叠、无归属碎片必须被门禁捕获，不得弹普通成功提示 |
| 跨阅读器 | 指定桌面WPS、Microsoft Word、LibreOffice版本实际打开/编辑/导出；微信/手机WPS单列设备验证，未测就明确未测 |
| 稳定性 | 取消、超限、损坏、密码、重开20轮、输出唯一命名、中文路径和资源回收通过 |

还应区分几何正确、字符正确和数学含义正确。文本计数相等不代表顺序正确，公式截图相似不代表可编辑，OMML可打开不代表表达式正确。

## 15. 实施顺序

| 工作包 | 交付 | 放行依据 |
| --- | --- | --- |
| P0 质量门禁与基线 | 冻结两个用户样本及匿名统计，构造短页/剪切/分式/线条夹具，失败检测入口 | 能检测当前失败，不再以生成文件作为成功证据 |
| P1 文字几何与图形归属 | 剪切/字体规范化、笔画分类、区域图及所有权 | 正文恢复，细线不成段，隐藏内容保护通过；不能只看可编辑率 |
| P2 混合布局与目标页 | LineBox、公式图像基线、题块、真实连续模式、短页/表格适配 | 44页样本首先达到完整可读，普通PDF不回归 |
| P3 本地公式语义 | 基础公式族OMML，再矩阵/分段/上下限，歧义局部回退 | 人工真值和真实渲染双验收，可靠公式真正可编辑 |
| P4 可选AI深度辅助 | 区域schema 2、来源绑定AST候选、局部复核和缓存 | 非模拟效果有证据，无静默改字，失败保留本地结果 |
| P5 独立回归与交付 | 留出集、跨阅读器、资源性能、维护记录、授权后的测试包 | 上述阻断项全部关闭；剩余限制明确，不将计划写成完成 |

P0/P1是基础缺陷修正；P2是版面可用门槛；P3才是复杂数学可编辑能力；P4不能代替P1-P3。每包先获得真实样本结果再进入下一包，进度按验收证据更新，不按已写代码行数估计。

首次正式实现前先将P0/P1收敛为可独立回归的改动，保留已验证的普通PDF路径。不得用全局放宽可见性判断、自动整页图片化或强制安装大型依赖来快速“通过”。
