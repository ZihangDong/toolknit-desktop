# V3.3 PDF 转 Word：转换流程与编辑保真重构规划

> 状态：调查与设计，尚未实施。2026-11-06。适用于当前 V3.3 开发工作区，不代表正式版能力或验收结果。

核心结论：需要同时修复内置编辑的样式数据与渲染切换，并完善扫描页的几何、表格和图层重建。推荐采用“纯转换页 → 只读选页 → 共享编辑界面的 Word 模式”，编辑后仍输出 Word。现有复杂样本尚不能判为 16/20 完美；只搬界面不能完成目标。

## 1. 本轮目标与已确认需求

本轮只检查源码、运行隔离探针、评估样本并制定实施方案。调查开始于北京时间 16:46:28，要求至少持续两小时；结束时间和最终验证在报告末尾补记。既有 OCR 等未提交改动保持原状。

用户已经确认：样式变化发生在 ToolKnit 内置编辑器；同一文件用 WPS 编辑正常。后续“编辑文档”复用 PDF 编辑器的界面与操作，但必须保留文档结构，编辑后仍能导出 Word。不能把 DOCX 简单转成 PDF 后重解析来代替这条能力。

截图中的英语词汇原稿本轮尚未定位；本报告通过独立真实 PDF 和受控混合样式复现同类缺陷，没有把截图重建件冒充用户原件。用户对 WPS 的确认针对其测试文件，不等于本轮所有复杂样本都已在 WPS 通过。

### 1.1 确定保留与删除的产品行为

| 位置 | 最终行为 |
| --- | --- |
| PDF 转 Word 首页 | 上传、文件状态、开始/取消处理、必要说明；复用现有转换工具布局，不放编辑器 |
| 解析与排版 | 桌面端只保留本地、原页布局；删除 AI 辅助排版、A4 重排入口及其桌面状态 |
| 单页文件 | 校验通过后直接处理，不弹出没有意义的选页选择 |
| 多页文件 | 先选择“全部处理”或“选页”；不在尚未决定时进行整份 OCR/转换 |
| 选页工作台 | 左侧大预览、右侧页面选择；只读，不能修改原文档；固定确认区；至少选择一页 |
| 选页返回 | 销毁本次导入会话，回到空上传页；再次处理需重新上传 |
| 确认页码 | 保存规范化、去重、按原稿排序的页码；释放选页视图，回到转换状态页处理 |
| 成功弹框 | 仅“编辑文档”“打开所在文件夹”“关闭”；不再有内置转换预览或打开原始 PDF 的歧义入口 |
| 编辑文档 | 转交结构化 Word 会话到文档编辑界面；源转换页重置；编辑后仍导出 DOCX |
| 打开所在文件夹 | 传入实际输出文件，使用系统资源管理器打开并选中；保留成功弹框供后续操作 |
| 关闭成功弹框 | 清理运行数据并重置上传页；保留已经成功写出的 DOCX，不删除用户成果 |

所有“销毁”均指会话、预览和运行资源释放，不等于卸载工具脚本，也不等于删除原文件或已保存结果。被转交的资源先更换唯一 owner，再释放来源页，不能边交接边释放仍被目标使用的数据。

成功弹框不展示引擎账本、自检分数或“已检查”复选框。若确有复杂区域保留图片，只用一行可理解的结果说明，避免用户误以为全部可编辑；不能用“完美”“100%”标签代替实际验收。

## 2. 已定位的根因

### 2.1 首次编辑切换整页渲染器

`src/features/pdf-to-word/controller.js` 的 `showPage()` 在未编辑时使用 PDF.js 显示原稿；`editor.dirty` 后改为 `renderResultPage()` 重绘整页。前者使用 PDF 绘制指令、嵌入字形与原位置；后者依赖系统替代字体与简化 Canvas 绘制。一次局部编辑会使未编辑的标题、正文、表格文字也全部进入另一条渲染路径。

真实浏览器隔离复现：产品方案中只打开一个短字段并原样保存，场景中仅一个 block 改变，但同尺寸画布有 45,676 个像素的任一通道变化超过 16；论文修改一个区域后为 130,034 个像素。两次均无 pageerror，无外部 POST。此数字用于说明整页变化，不能当成文字正确率或最终画质评分。

追加跨页复现：只在第 1 页原样保存后，再查看没有编辑的第 2 页，同尺寸画布仍有 36,945 个像素显著变化，虽然第 2 页场景数据未变。`dirty` 是全局条件，因此影响不限于被编辑的页面。已有“其它页 JSON 不变”测试无法捕获这个显示缺陷。

一致渲染隔离实验中，使用同一个现有场景 renderer 渲染修改前后结果，追加“123”仅改变 312 个像素，编辑区域外扩 3pt 以外变化为 0。这证明取消渲染器切换能隔离全局外观跳变；它没有修复现有 renderer 的字体精度或整段样式丢失，也不代表新编辑器已经实现。

### 2.2 文本替换丢失片段样式

`core/result-edit.js` 将多个文字片段拼成纯文本，以一个代表字号布局；`applyResultEdits()` 把替换行重建为单个 item，并复制第一个 item 的字体、粗斜体和颜色，还把被修改段落改成左对齐。原来的混合字体、局部字号、基线变化、字距与水平缩放不能完整保留。

受控混合样式探针中，12pt Arial + 15pt 加粗衬线文字原样保存后成为一个 15pt Arial 片段；单字符替换后还可能被整体缩到 14.5pt。八份真实文档抽取的 31 个可编辑目标，原样保存后都产生了结构变化。结构变化本身并不一定可见，但它说明当前缺少 no-op 短路；混合样式丢失已由字段级对照证实。

另制作不计入正式文件数量的两栏音标夹具。英文 Arial、斜体 Times New Roman 音标、Noto 中文共 3 个 run，追加“123”后成为 1 个 Arial run，原两种颜色变成一种；音标和中文字符串仍在，所以仅检查“导出文字没有丢”会误判通过。

### 2.3 预览和 DOCX 没有共用足够完整的排版结果

`result-preview.js` 使用 `fillText()`，未完整复现 DOCX Writer 的字体测量、字距、基线校准与定位片段。`adapters/docx.js` 已有较成熟的逐 run、twip、半磅与阅读器适配。不能为修复内置编辑器而无依据地全量重写已被用户验证正常的 Word 输出。

### 2.4 当前 PDF 编辑器的输入边界

现有 `pdf-editor/file-session.js` 只接收 PDF；`openWithFile()` 不能直接打开 DOCX。普通 PDF 文本修改另走 PDF-lib 字体替换及遮盖重写，无法自动保留 Word 表格、run 和 DOCX 回写结构。需要共享编辑界面，并保留不同文档模式的数据适配器。

### 2.5 OCR 的识别结果与文档重建质量是两件事

复杂表格探针确认了额外问题：

- `core/ocr-scene.js` 将 OCR 行框扩展后，在大矩形内推算笔画、颜色和字号。彩底、边线或邻行混入时，某些普通表格文字被推算为约 24–28pt，并把蓝色底纹当成文字颜色。模型本身能读对多数文字，不代表这些几何值正确。
- Native OCR 返回 `polygon` 和 `words`，但当前 Word 重建主要消费行矩形和整行文本。可以优先利用已有细粒度信息，不必一开始就换大模型。
- OCR 重建的线条来源取自 `result.rules`，没有合并原生场景已有的矢量线条。一份样本有 256 条原生线条，但栅格线检测返回 0。隔离合并探针恢复了部分网格，但仍有单元格容量失败，说明不能只做“合并数组”就宣告表格已修好。
- `ruled_lines()` 目前以深色阈值检测直线，浅蓝/彩色表格边框会漏检；有线网格和无框列布局也必须分开判断。
- 部分 OCR 行因复杂背景被保留在图像中，之后来源账本主要围绕留下的识别文字重新构造。“当前账本里 100% 可编辑”并不能证明原稿所有可见文字都被识别并恢复。必须独立核对输入证据、残留背景和目标文档。

实施时保留原生可见文字的可信内容与几何，OCR 只补缺失区；保留被回退但仍可验证的候选来源。字体推算使用局部背景、真实字形连通区域与行/单元格约束，排除底纹和长线，不能继续用一个固定的高度乘数覆盖所有字体。

还需修正 OCR 文字进入 Writer 的路径：当前 OCR item 为 `preciseInk:false`，会进入普通 `textRuns()`，没有完整使用 `advanceWidth` 和词级位置。只改字体高度仍不能保证行宽、字距和基线，需要把校准后的 run/词位置送入共用布局规则；不能未经校准直接把标志改成 true。

### 2.6 全选资源上限与复杂网格失败

整份压力检查新增两个真实失败：

- 44 页图文原稿输入约 40.43MiB，低于输入上限，抽样成功但全页在处理约前 19 页时触发 `asset-large`。这与旧的 `INVALID ARRAY LENGTH` 不是同一原因。现有代码已经有照片 JPEG 编码和图像 fingerprint，不能报告成“没有压缩”；还需要按来源分辨率、可见区域和内容类别优化，并真正复用相同资产的存储预算。
- 中文工程图扫描衍生件触发 `coverage`。隔离后确认同一个 OCR 来源被两个重叠网格同时认领；一个网格回退图片后，仍与保留表格共用该来源。覆盖检查正确阻止了坏输出，修复方向是全局来源/图层归属，不能吞掉 coverage 错误。

图表/工程图不能仅因线条组成矩形就被当成数据表格。必要的嵌套应表达为一棵层级结构，或者选取有充分行列证据的网格；每个可见文字只归一个叶节点。回退时不能只从账本删重复 ID，还必须防止外层恢复原像素后又把内层可编辑字重复画一遍。

## 3. 推荐的整体结构

### 3.1 一个转换引擎、一份结构化文档、两个职责清楚的界面

```text
本地 PDF 输入会话
  ├─ 只读选页视图：PDF.js 原稿预览 + 页码集合
  └─ 本地转换：原生文字优先 → 必要页 OCR → 版面/表格/公式 → WordScene
       ├─ DOCX Writer → 校验/原子保存 → 成功弹框
       └─ 可交接会话：WordScene + 资产 + 字体/度量 + 编辑基线
            → 共享文档编辑界面（Word 模式）
            → 局部编辑事务 → 同一 DOCX Writer → 新结果
```

转换页不再提供编辑功能。选页视图只借用 PDF 预览和页面选择组件，不启动完整编辑器、文字分析或 Word 导出。编辑页使用 WordScene，不重新从 DOCX/PDF 猜测已经得到的结构。

成功保存后即可释放原稿 PDF.js document、输入字节和原稿预览，仅保留 WordScene/必要资产供成功弹框交接。编辑器本轮不新增“原稿对照”功能，因此没有理由继续持有整份原 PDF；PDF 输入资源与 Word 结果资源应有不同释放入口。

### 3.2 复用方式与边界

- 共享工具导航、上传空状态、加载遮罩、结果弹框行为及视觉组件、输出路径与焦点管理。
- 只读选页优先扩展 `shared/pdf-workbench.js` 的布局变体，复用指针缩放、预览取消、缩略图队列和页面状态；禁止复制完整 PDF 编辑器控制器。
- 将文档编辑界面的导航、预览容器、页列表、通用选中状态、文本编辑交互、撤销/重做和弹框提炼为共享 shell；保留原生 PDF 与 WordScene 各自的文档适配器。
- 应用组合层注册/注入 Word 模式适配器，feature 之间不直接互相 import。PDF 编辑器既有 `openWithFile()` 保持 PDF 契约；新增明确的结构化会话入口，不能让旧方法根据后缀暗中走另一种解析器。
- 通用 shell 不包含受专属条约约束的 PDF→Word 引擎实现。迁移专属模块时保留 SPDX、归属和许可范围。
- 原生 PDF 模式继续使用既有文件、导出和页面逻辑。Word 模式仅暴露已实现并验证的能力，不显示实际仍会调用 PDF-only 导出链路的按钮。

共享 shell 只消费模式能力、标签与文档适配器，不持有转换业务。Word 适配器按需加载；普通 PDF 编辑不预加载 Word Writer、OCR 或公式模型，避免这轮复用反过来拖慢其它工具。

实现顺序是先建立适配器契约与兼容测试，再提取最小公共 UI；不先大拆现有 2,000 行控制器，也不以复制一套控制器作为“复用”。

### 3.3 编辑器模式能力表

| 能力 | 原生 PDF | 转换后的 Word |
| --- | --- | --- |
| 预览、缩放、分页、页面选择 | 保留 | 共用界面，使用 WordScene renderer |
| 文本编辑、删除、撤销/重做 | 保留 | 片段级样式编辑事务 |
| 图像选择、替换、删除 | 保留 | 通过 assetId 和原边界编辑 |
| 表格内部文字选择 | 保留既有行为 | 单元格/文本优先，背景与边框不能拦截 |
| Word 导出 | 不新增隐式格式转换 | 必须支持；初始/编辑后均走同一 Writer |
| PDF 专属动作 | 保留 | 无对应实现时隐藏，不伪装可用 |

Word 模式标题明确为“文档编辑 · Word”，主按钮明确“导出 Word”；不让用户误以为当前保存的是 PDF。已有 PDF 编辑器首页名称和文件上传入口保持原含义。转换选页后的编辑页默认全选这些结果页，按编辑器当前选择/顺序导出；编辑器页序与原 PDF 页码分别显示，例如“第 2/3 页 · 原第 7 页”。页面使用稳定 ID，不能用数组下标充当来源 ID。

Word 模式需要页面旋转/复制/删除等操作时必须有对应场景和 DOCX 实现及测试；首轮未实现的动作隐藏，不能让 UI 看似响应、导出却忽略改动。用户从此模式返回后，来源转换页应是空状态。关闭有未保存改动的文档保留确认机制，已导出的文件始终保留。

## 4. 字体与编辑稳定性的具体方案

### 4.1 一开始就显示同一份文档

进入 Word 编辑模式时即显示转换后的结构化文档；后续局部修改继续走同一 renderer。原稿 PDF.js 仅用于原稿选页与独立对照，不再以“未改过”为条件切换渲染器。

提取并复用 Writer 的纯样式解析与测量规则，形成一次解析的 `resolvedStyle` 和位置结果：字体身份、大小、粗斜体、颜色、字距、基线、advance、横向比例、书写方向和片段边界。Canvas、命中框和 DOCX 输出消费同一结果，不能各自再猜一遍字体或字号。Canvas 点坐标与 CSS 像素的缩放只在视图边界进行，DOCX twip/半磅只在序列化边界取整，避免重复换算。

预览还须表达真实单元格边框、合并关系、背景和图片层级；不能只把所有格子画成同一种灰框。公式沿用有来源证据的结构/图像表示。字体按页准备好后再呈现，避免字体异步加载造成第二次跳动。

命中优先级按对象层级与实际可编辑叶节点处理：文本/单元格优先于覆盖它们的背景，背景不能截获文字点击。源文字被清掉后的背景、单元格底色、边框和图像要有明确归属；删除/替换不能留下旧字或错误抹掉旁边图像。普通文本编辑不跨过公式对象把它展平成字符串。

### 4.2 保留 run，而非重新创建整段

1. 保存前按真实字符比较；仅统一输入控件的 CRLF/LF，不能 trim 或做 NFKC 把上标、全角符号等折叠成另一个字符。未修改则直接关闭，不建立编辑记录，不改变 dirty 状态，不重排。
2. 用户修改记录为字符范围事务，保留来源 run ID 与偏移映射。替换一字只更新对应片段；未受影响片段的字体、字号、颜色、基线与字距原样保留。
3. 插入字符继承光标位置的样式；删除字符不合并原本样式不同的片段。混合字号、音标、中西文、上下标和组合字符分别验证。
4. 优先记录输入范围，兼容 textarea 时用有界差异算法恢复范围；不能对 10,000 字输入运行无界二次复杂度 LCS。按 Unicode grapheme 处理编辑，明确 UTF-16 选择位置与字符序列的映射。
5. 不因局部修改而更换段落对齐、重建所有行或改变邻居的布局。段落、栏和单元格均保留真实约束。
6. 自动排版顺序：保留原字号 → 使用当前栏/单元格确有的剩余空间 → 在同一区域换行 → 必要时仅对受影响内容做有界适配。不能把整个混合段落统一缩小。
7. 放不下时保留原内容并给出明确可恢复提示；不静默覆盖邻文、截断内容或移到其他栏。用户无需自行调字号，但自动适配不能牺牲未编辑内容。

### 4.3 字体缺失与子集字体

PDF 嵌入字体可能是只含原字符的子集。原字符可以绘制，不代表新增中文或音标也有 glyph。字体身份、字形覆盖与度量应分别判断；禁止把缺字方框的宽度当成真实字宽。

优先使用当前 Writer 已验证的字体解析；原字体可合法且技术上可加载时保留会话内字体资源。新增字符缺字时仅对受影响片段选择可用替代，不替换整页。导出文件中的字体仍受目标阅读器与本机字体影响，须在实际 WPS/Word 中验收；不能用浏览器字体存在代替跨机证据，也不默认再分发用户电脑上的字体文件。

这里的第一目标是保持“转换后的 Word 样式”在本机编辑前后一致。不能为让预览暂时像原 PDF 而使用一套仅预览存在的嵌入字体，实际 DOCX 却使用另一套替代字体。跨机器原字形保真属于额外字体能力，只有嵌入权限、字形覆盖和目标阅读器都验证后才启用；不作为修复当前编辑跳变的前置依赖。

### 4.4 不采用的捷径

| 方案 | 未采用原因 |
| --- | --- |
| 继续显示原 PDF，编辑后才切换场景 | 正是当前整页变样的来源 |
| 原 PDF 截图上直接白色遮盖改字 | 彩色背景、表格边线、透明图层易被破坏，旧字可能残留；不能作为通用编辑基础 |
| DOCX→PDF→重解析再编辑 | Word 表格/样式结构丢失，多一道转换和依赖，不能可靠回写 DOCX |
| 所有内容改成图像+隐形文字 | 看似保真，但不满足真实可编辑和表格要求 |
| 先内嵌大型在线 Office | 网络/数据/部署与本地定位不符，也绕开了当前引擎的具体缺陷 |

## 5. 转换流程与会话所有权

### 5.1 状态机

```text
empty → probing → single-page / choose-scope
single-page / all-confirmed → converting → saving → success
choose-scope → selecting → selected-confirmed → converting
selecting.back / scope.cancel → release → empty
success.close → release → empty
success.edit → transfer.prepare → editor.accept → transfer.commit → converter.empty
失败/取消 → 停止当前任务 → 清理临时产物 → 可重新上传或明确重试
```

操作开始时同步设置 busy 并显示遮罩，再让出一帧后执行重工作。导入只做类型、大小、密码、页数与必要元数据检查；选择范围前不整份 OCR，不生成全量高分辨率缩略图。

每次处理一份 PDF，保留单文件校验。范围弹框、选页、转换和交接状态不接受第二份隐式拖入；返回清空后才重新上传。借用转换页布局不额外引入多文件队列、自动合并或其它本轮未请求的能力。

### 5.2 选页交互

进入“选页”后默认不选，当前预览页与选择集合独立。提供全选、清空、反选和可重复追加范围输入；`1-10` 后追加 `15-20` 不包含 11–14。按钮显示“处理已选 N 页”，N=0 时禁用。点击缩略图主体切换预览，明确的选择控件切换选中；支持键盘、范围选择及可读的选中状态。

右侧选择区与底部确认区固定，页面列表独立滚动；左侧预览按鼠标缩放。低高度窗口、长文件名、中英文和深浅主题均使用同一组件规则。不能直接全局调整所有 PDF workbench 的列顺序来满足这一页。

界面草图：

```text
转换页：共用导航
        功能说明/三步提示 | 上传或文件状态卡
                         | 开始处理/取消/重试
        （这里没有页缩略图、画布或编辑按钮）

选页页：共用导航，返回即清空本次导入
        左侧：当前页预览、缩放 | 右侧：已选 N 页、全选/清空/范围
                              |       按需缩略图列表，独立滚动
                              |       固定按钮“处理已选 N 页”

编辑页：共用编辑导航，模式明确为 Word
        页列表 | 转换后文档预览/选中框 | 当前对象操作
        按模式显示操作，主动作“导出 Word”
```

只读页不得启动文本选区、编辑快捷键或右侧对象工具。工作台布局变体默认关闭，其他 PDF 工具维持原参数；每个可见模式只保留一套导航。应用背景适配深浅主题，文档纸面保持原稿颜色；不能为深色模式反转实际文档颜色。成功弹框沿用通用样式，三个按钮按实际可用宽度换行，不裁切或省略按钮文字。

### 5.3 安全交接，不重做转换

应用级临时会话 broker 管理一次性 ticket：来源 generation、结果路径、来源页映射、WordScene、资产/字体租约、当前有效状态。目标先验证版本/资源/预算并接管，再确认来源释放。失败则回收未接管资源并保持已保存结果可用；不能在目标尚未打开时丢弃唯一的结构化数据。

已复核 lazy registry：激活新工具会先关闭旧工具。因此实际顺序必须是“预检 → 将必要资源从来源会话脱离并交给 broker → 调用工具导航 → 目标验证并接收 → 提交所有权”，不能只是把来源对象的引用塞进参数后直接 `close()`。broker 在导航期间是唯一 owner；失败时从 broker 恢复可重试的成功状态或明确保留输出路径，绝不恢复旧预览 DOM。最多保留一个待交接会话，超期/关闭/应用退出回收，避免失败票据长期积累。

会话仅在本机内存/受控临时目录使用；不把私人内容写入 localStorage、日志、URL 或公共文档。关闭目标编辑器后释放相关租约。切换到已有未保存文档时沿用编辑器的放弃确认；取消放弃则交接失败可重试，既有文档不得被覆盖。

本次保证的是从转换结果进入结构化编辑并再次导出标准 DOCX。不能据此宣称已支持任意外部 DOCX 的无损再导入。会话退出后，标准文件仍可由 WPS/Word 编辑；不为实现会话回开而把原始 PDF、未选页或包含隐藏内容的内部账本塞入 DOCX。

### 5.4 资源清理清单

| 资源 | 来源页返回/关闭 | 选页确认 | 转交编辑器 |
| --- | --- | --- | --- |
| 输入字节/受控文件引用 | 释放引用，不删原件 | 转换会话接管 | 仅确实需要的会话资源转交 |
| PDF.js document/loadingTask | cancel/destroy | 仍需转换时转交 owner；视图任务先停 | 成功后已释放，不转交整份原 PDF |
| 缩略图/预览 Canvas、RAF、observer | 释放/置零 | 全部释放 | 不携带旧 DOM/Canvas |
| 转换 Worker/资产 | 取消并终止 | 转换任务持有 | 目标接管或转为明确的 asset store，避免结构化复制双份大图 |
| 进度监听/AbortController/密码 | 解除并清空 | 新任务 generation | 不延用旧取消信号 |
| 成功 DOCX 文件 | 保留 | 不适用 | 路径保留，新编辑结果默认另存唯一文件 |

懒加载注册表会缓存 controller。释放会话不等于对缓存实例永久 `dispose()`；重复打开必须可用，返回/Escape/工具切换/迟到 Worker 结果都不能恢复已清除页面。

保留现有 PDF 编辑器 reset 的正确顺序：先同步脱离当前 UI/数据，再等待旧 PDF.js document 销毁；旧异步清理不得清掉新 Word 模式。接管 ticket 时同时核对目标活动工具、导航代次和票据状态，不仅核对结果路径存在。

### 5.5 输入与失败边界

当前集中限制基线是：输入/输出各 64MiB、来源最多 300 页、单次选中最多 100 页、资产 32MiB、估计工作内存 512MiB、渲染 16MP、任务超时 10 分钟。UI 重构不自动扩大字节/页数限制；资产与扫描时限调整按本轮实测另行验证，集中修改配置与契约，不在控制器写第二套常量。

“全部处理”超过单次页数限制时不能截断前 100 页或假装成功。首轮保留现有限制，在范围弹框给出上限并引导选页；后续若支持更大整份输出，必须先证明最终 DOCX 打包与资产内存有界，不能只把页面循环分批就声称可流式无限处理。

加密文件复用密码交互，不持久化密码。损坏、空文件、无权限、模型缺失、下载取消、磁盘不足、输出文件夹失效和写入失败均给出具体可恢复反馈。OCR 依赖确认只在真正需要 OCR 时触发，沿用现有七彩云下载与本地校验链路。

当前原页 Writer 还限制纸张单边不超过 1584pt，超过时应在处理前准确提示，不因去掉 A4 选项而偷偷把大纸张缩成 A4。最终渲染像素上限也不等于 PDF 内嵌图片解码峰值已受控；大图压力测试须分别量源图片解码、页面画布和资产打包。

扫描长文档还需要重新分配任务时限：原生 OCR 目前单页硬上限为 120 秒，转换前端整份固定 10 分钟。本轮单页实测约数秒至三十多秒，长扫描文件累计容易越界。实施时区分探测、下载/安装、单页推理、布局和写盘阶段；下载不计入转换 CPU 超时，单页保留独立看门狗，整份预算依据选中页数与真实 OCR 规模设定有界上限。超出支持范围要提前明确，不能无限等待，也不能未经测量仅把所有超时乘十。

建议首版预算按“冷启动余量 + 需要 OCR 的页数 × 本机矩阵 P95 页耗时 × 1.5 + 布局/写盘余量”估算，限制在 10–60 分钟内；这是待实现验证的初始策略，不是已经改变的产品行为。单页仍受独立上限约束，持续没有进度不能靠整份预算拖延。纯原生 CLI 路径保留原时限，扫描预算不扩散到其它工具。

## 6. 转换质量提升顺序

### 6.1 原生 PDF

先保留可见原生文字与字体来源，再按栏、行和单元格建立结构。PDF 提取到的隐藏/被覆盖文字不应直接恢复。表格先分配文字归属、后组行；图片、背景、边线与文字的来源只能认领一次。保留已经验证的短字段和背景文字恢复，不为提升表格率而放宽所有布局门禁。

### 6.2 扫描与混合 PDF

按页判断是否需要 OCR，原生文字优先并去重。OCR 输出的行框不是最终字体/字号/表格结构；应补行内基线、字形范围和单元格约束。去旧字必须保护线条、印章、图像和真实背景。不能用纯白遮盖应付彩底，也不能保留旧字再覆盖新字。

有线表格先优化现有几何算法：断线连接、线宽与边界容差、合并格、内容容量和单元格间隙。无框表格需稳定列与数值证据，避免把普通双栏或列表变成表格。若现有几何无法达到测试门槛，再评估按需表格结构模型，不先把大型模型加入所有截图 OCR 链路。

大图资产优化先沿用已经合成好的可见裁切，不把原始 XObject 全图直接塞进 Word，以免恢复裁切外/被遮盖内容。复用现有 fingerprint，分开“内容字节去重”和“每个来源的排除绘制证据”；相同像素不能令 provenance 校验失效。最终峰值包含 Worker、解码画布、资产、DOCX Packer 和写盘传输。

照片编码不能只依赖色彩饱和度：部分室内渲染图恰好低于当前 25% 彩色像素门槛，继续保留大 PNG。隔离编码对照提示有压缩空间，但不能把 Pillow 的 JPEG 体积当作 Chromium 正式输出，也不能把纯扫描文字/公式按照片压缩。先核对原图有效分辨率和灰阶连续色调，保留文字/公式无损；任何预算提高都以完整文档和实测峰值为前提，不只抬高 32MiB 常量。

### 6.3 常见公式

PP-OCRv5 的通用字符识别不等于数学结构识别。原生 PDF 可利用字形、笔画、基线和已有 AST/OMML；扫描公式没有这条原生来源，不能直接沿用“已支持公式”结论。

首轮明确覆盖算术符号、括号、等式、上下标、简单分数与根式等清单；每种有独立真值。纯文本表达能等价保留的按片段处理，二维公式需要结构识别与有界解析。识别结果只有通过符号、次序、上下标/分子分母和渲染几何校验后才计作可编辑公式。不能把公式图片计为原生公式达标。

额外核对：当前 Writer 的 `editableMath` 默认关闭，原生数学导出是内部验证通道；不能因为存在 OMML 测试就声称产品已开启原生公式。在双栏论文的两页探针中显式启用后得到 5 个原生公式，而另一份符号/表格页仍为 0；这只证明候选路径存在，尚不能替代目标阅读器局部外观和独立数学真值。扫描公式也不能把模型输出套上 PDF 的 `sourceId` 冒充同一证据，需要区分 raster 语义来源与 native glyph 来源。

已查阅 PaddleOCR 官方公式/表格模块说明，作为后备模型选型参考；官方速度是在指定服务器、指定后端上的推理数值，不是 ToolKnit 本机端到端测量。模型选型、ONNX 可运行性、解码器、内存和中文表现须先做隔离可行性实验。新模型若采用，仍只从七彩云分发，按需下载，不加入安装主包、不影响截图普通提字。

官方文档当前标示 SLANet_plus 约 6.9MB，适合作为轻量表格结构候选；SLANeXt 约 351MB，先不默认加入。公式模型 PP-FormulaNet-S 约 224MB，plus-M 约 592MB，后者说明支持中文公式；不能把通用 OCR 的约 20MB 模型包大小套用到公式识别。先验证小模型能否覆盖明确公式清单，再决定是否需要中文增强型号；模型输出只允许受限符号/结构，不能执行 LaTeX 命令或访问外部资源。

资料入口：[公式识别](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/module_usage/formula_recognition.md)、[表格结构识别](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/module_usage/table_structure_recognition.md)、[版面定位](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/module_usage/layout_detection.md)。此处为调研引用，不是新增产品下载源。

补充集不替换原 20 份，也不拿来更改先前通过率；两组原稿合计 28 个独立哈希。重复导出、全页扩展与栅格衍生件都不重复计算独立文件数。

### 7.2 正式验收集的要求

当前诊断集不是最终发布验收集。实施前再固定正式 20 份，至少 10 份中文或中英混排、8 份含扫描/混合页、8 份含表格、4 份含常见公式、6 份含图像；类别允许交叉。至少包含合并格、跨页表格、双栏、彩底/印章和真实用户文件。额外合成样本只用于边界探针，不用于凑 20 份。

每份均固定原稿哈希、完整测试范围、来源与独立真值。受当前上限约束时预先声明选页，不能事后只选择通过的页；优先选取可完整转换的文档作为正式投票样本。开发集与留出集分开，调参用过的不能再称未见；语言/类别缺口补充必须明示，不能把失败样本替换成容易成功的文件。

“达到八成”的定义是 20 份中至少 16 份同时通过该文档适用的全部质量门槛，不是 80% 字符可编辑，不是 80% 页面，也不是 20 次重复导出成功。

### 7.3 单份文档的通过门槛

| 维度 | 门槛与证据 |
| --- | --- |
| 完整性 | 无漏页、错页、重复页；原稿选页到输出页的映射正确；无新增空白页 |
| 文本 | 原生文字正确率建议 ≥99.5%，清晰扫描正文 ≥99%；金额、日期、题号、单位和独立核对的关键字段必须全对；以人工/可信来源真值为准 |
| 编辑性 | 可读正文与表格文字编辑覆盖建议 ≥98%；不能把图像内文字、透明隐藏字或错误识别的自有账本计作通过 |
| 位置 | 关键锚点、栏与单元格归属正确；文字基线位置建议 P95 ≤1pt、关键字段 ≤1pt；不得重叠/越格/跨栏；扫描 nominal 字体无法确知时以可见字形几何验收 |
| 外观 | 每页前景 F1 建议 ≥0.95，表格、公式和关键字段另做局部对照；不让大图或空白掩盖小区域错误 |
| 表格 | 应为表格的区域形成真实可编辑表格；行列、合并格、内容归属、边线/底色正确；删除或修改单元格后没有旧字残留 |
| 图像 | 保留必要图像、位置、裁切、层级和比例；不把正文整页吞入图片来提高外观分数 |
| 公式 | 清单内常见公式符号与二维关系正确；可编辑公式须为正确结构，分子分母、上下标不能互换；公式图片单列，不能冒充通过 |
| 编辑稳定 | 原样保存不产生编辑；一字替换不改变未编辑 run 的样式与几何；撤销/重做/重置恢复一致；有空间时追加“123”不缩小字号 |
| 阅读器 | 内置 Word 模式与实际 WPS 检查；Word 可用时追加 Word；LibreOffice 仅是额外兼容证据，不能冒称全部阅读器均通过 |

以上是实施验收建议值，需随正式真值标注固定后执行，不能为了凑到 16/20 临时放宽。任何金额错、正文缺失、隐藏内容泄漏、旧字重影、跨栏覆盖、公式语义错误，均直接判该文档不通过。

若不足 16/20，保留失败证据、按缺陷类型修复后重跑原样本；不能以“复杂文件本来就难”把失败改写成完美，也不承诺所有未知文档都能 100% 还原。

同时检查类别分布，不能用普通文本全通过掩盖扫描表格/常见公式全失败。正式矩阵应对核心类别设覆盖门槛，并至少拿出真实中文扫描表格和扫描公式的成功证据。

### 9.1 性能与资源门槛

- busy/遮罩在首个可呈现帧出现，不等加载/解析结束；以本机测量为准，目标通常为两帧内或 100ms 内。
- 页面切换只刷新当前预览；缩略图惰性、并发和像素预算有界；不为一次勾选重画所有页。
- OCR 单会话复用模型，按需页执行，避免同一页为预览/导出/编辑重复识别；记录真实冷启动、温态、推理、排版和写盘分项耗时。
- 转换主页面没有高分辨率编辑预览，降低无效渲染；重计算继续在既有 Worker/原生任务中处理，取消能让界面立即响应。
- 最终打包峰值也计入内存；分块保存不等于 DOCX 生成已流式。记录大量图像、全选和重复打开 20 次的峰值/回收曲线，不能只看单次成功。
- 原图、已保存结果和用户模型均不因重置删除；取消后的临时文件、监听、任务与资产回到基线。

### 9.2 测试与维护

实施后先 focused tests，再按影响运行架构/build、release/security、CLI 与 Rust 门禁；共享编辑器和选页布局必须抽查既有 PDF 编辑/拆分/合并/转图工具。原生命令或 CLI 依赖改变时追加独立安装包/CLI 导入检查。

浏览器矩阵覆盖中英文、深浅主题、1366×768 与低高度窗口、Tab/Escape、首次/重开/取消/失败、焦点与 inert、重复点击、快速切页、选页滚动和指针缩放。真实桌面验证保存、文件夹选中和交接；不以注入识别结果冒充 Tauri 完整流程。

## 10. 方案复核记录

第一次复核发现并修正：导航会先关闭来源，交接必须经过独立 broker；“全部处理”不能越过 100 页限制；CLI 仍消费 AI/A4，因此桌面清理不能直接删引擎；OCR 字符准确不代表字号/层级正确；当前 20 份诊断集中文占比不足，不应直接作为最终发布投票集。

第二次复核已补充：Word 模式明确输出格式与原页映射；原生公式默认并未开启；扫描公式必须有独立证据路径；字体稳定优先保持实际 DOCX 的解析结果，不在预览和导出各用一套；长扫描文档需要分阶段有界时限。

字号隔离实验比较了检测框高度、字形连通区域分位高度、完整字形并集及实际字体轮廓测量。去掉底纹/长线能改善一些表格，但单纯取分位会丢下伸部，简单并集又会吸收邻行，一套固定高度比例不能通用。最终采用“来源字体优先；扫描按多边形/词框与行约束去噪、测实际 glyph、宽高双向校验”，而不是把旧的 1.13 换成另一个魔法系数。

第三次复核（基于整份文件和中文补充集）调整了实施范围：增加资产累积预算、重复网格来源归属与实际 OCR Writer 路径；把“原样保存”“未编辑页外观不变”“文字还在但样式变了”列为互相独立的门槛。覆盖检查继续 fail closed，不以隐藏错误通过测试。
