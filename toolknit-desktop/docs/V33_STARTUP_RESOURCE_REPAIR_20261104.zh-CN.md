# V3.3 启动卡顿排查与资源修补

日期：2026-11-04。开发分支 V3.3，未发布。

## 现场结论

- 用户反馈刚进入测试版即卡顿，随后确认重新打开首页已恢复流畅；恢复发生在新代码应用前，不能记为修复验收。
- 采样时 Rust 主进程基本空闲，文件搜索加速服务未运行，搜索页仍为首次启用引导。没有证据将本次卡顿归因于全盘索引。
- 主 WebView 浏览器进程曾持续占用 CPU，私有内存升高后又回落；不能据此直接认定持续内存泄漏。
- 原生控制台留有音频设备/WebAudio 渲染错误。首页浏览器对照没有发现持续 JavaScript 回调循环，主要持续开销来自动画渲染。
- 窗口截图接口超时，原生键鼠诊断也有焦点限制。原生现场只能作为症状线索，尚未完整复现最初的间歇卡顿。

## 已确认并修补的问题

1. `src/app/ui-sound-controller.js` 在 AudioContext 暂停时仍创建和排定音效，依赖音频时钟触发 ended 清理。设备异常或时钟停滞可能积累节点；失焦只暂停、dispose 只移除监听，也没有完整释放音频图。
   - 只在 running 状态创建声音节点；合并恢复请求，失败退避。
   - 最大保留 8 个短音效；ended 和墙上时钟超时双重清理。
   - 失焦、隐藏、音频状态改变和 dispose 释放节点；迟到的恢复不在失焦后重开音频。
   - 保持音效设置、声音风格及现有全局 API，不更改用户偏好。
2. `src/styles/layout.css` 的透明过渡遮罩、`src/styles/pages/account-feedback.css` 的隐藏反馈页仍运行 CSS 动画。
   - 遮罩隐藏时暂停精灵动画。
   - 反馈页隐藏或 inert 时暂停本页动画和伪元素动画；显示时保留原效果。
