## 可验收功能

### 首页

- 分类名称为“V3.2新功能”，位于“全部”之后。
- 展示快速截图、PDF 转扫描件、清理重复文件、PDF 转 Word、剪贴板历史、图像转 PDF 六张卡片，原业务分类保持可用。
- 当前为 73 个桌面工具、12 个业务分类；PDF 分类 16 项，CLI/MCP 仍为 46 项。

### 图像转 PDF

- 独立三栏工作台：左侧参数，中间预览，右侧页面列表；支持中英文、白天和深色主题。
- 读取 JPG、PNG、BMP、WebP、GIF，以及桌面端的常见 TIFF。支持多图合并、继续追加、自然排序、手动排序、删除、旋转和缩放。
- A4 自动方向、指定横纵向、0/8/15 mm 边距；原图纸幅读取有效物理分辨率，缺失时按 96 DPI。
- 原彩、灰度、扫描质感；高清、均衡、小文件三档质量。透明区域铺白底，照片方向自动校正，动态图像取首帧，多页 TIFF 逐帧展开。
- 损坏、不支持或超限的输入单独列出，可逐项或批量移除失败条目，不静默漏页。
- 使用统一输出目录的 Image_PDF 子目录；重名另存，完成后可打开 PDF 或定位文件。原图保持不变。

### PDF 编辑器

- 无需上传文件即可新建 A4 PDF；空状态按钮和侧栏“空白页”均可创建第一张纸。
- 继续添加空白页时继承当前页的可见纸幅，包括横向、旋转和小尺寸标签页；同纸幅复用不可变源字节，各页保留独立编辑身份。
- 新增文字支持多行、空行、Enter 换行、Ctrl+Enter 保存；预览、选框和导出使用相同行距。初次放置靠近页边时移回页内，过大的初始内容按纸幅适配。
- 图片、形状和文字跟随页面旋转正确显示；旋转对象缩放时方向正确，对侧节点保持固定。
- 删除图片或页面后撤销，原图会恢复到预览和实际导出；复制页、撤销重做、重置及保存状态经过联合验证。

## 本轮定位并修复的问题

| 问题 | 处理结果 |
| --- | --- |
| 删除图片后撤销只恢复选框，导出丢图 | 原图字节由当前、历史、基线和已保存快照共同持有，最后一处引用释放后才清理 |
| 撤销后新对象复用旧编号 | 对象编号保持递增，避免与已保存或可重做的内容混淆 |
| 新建文档被误当作已保存，重置后提示状态不准 | 区分初始基线与实际导出快照，单纯缩放和选页不计为内容修改 |
| 损坏或超页数文件加载失败后后台线程未释放 | 通过 PDF.js loadingTask 回收失败任务，关闭先解绑旧资源再异步销毁 |
| 追加文件读取期间没有任务保护 | 先建立任务，再读取与解析；异步边界检查取消，容量使用实际读取字节 |
| 旧原生文件选择结果进入新文档 | 校验文件选择开始时的文档身份 |
| Escape 关闭文字弹框后继续触发关闭文档 | 消费当前弹框事件并停止传播 |
| 中文输入法回车可能触发保存 | 忽略输入法组合阶段的提交快捷键 |
| 保存已开始写盘却仍接受取消 | 最终提交阶段禁用取消，避免成功文件被报告为取消 |
| 添加空白页时迟到的页面尺寸结果继续写入 | getPage 返回后再次检查任务，并回收页面资源 |
| 页面旋转后图像被拉伸，预览方向与 PDF 不同 | 保留对象本身尺寸，统一页面角度、对象角度和中心位置映射 |
| 旋转对象的缩放方向反了，对侧节点漂移 | 校正屏幕与 PDF 角度符号，并旋转中心位移以固定对侧节点 |
| 很小图片的 A4 边距被低分辨率画布吞掉 | 页面画布保留足够像素表示边距，原图解码仍不伪造细节 |
| 透明图缩小时产生暗边 | 原生解码先在白底合成，再进行滤波缩放 |
| 损坏的 WebP EXIF 长度可能越过块边界 | 在已验证的 chunk 范围内解析可选前缀，并增加截断测试 |

### 性能和资源

已完成的百页测量：100 张 1200×1600 合成文档图导入约 4.26 秒，高清导出约 19.42 秒，结果约 33.5 MB；导出阶段主线程 longtask 计数为 0。20 次图像工具重开后 URL/Worker 归零，主线程堆约 8.3 MB。

500 页 PDF 初始加载约 0.37 秒，活动缩略图画布 19 张；501 页替换被拒绝后，原 500 页仍可完整导出。以上是本机样本测量，不能推算成所有电脑、全部文件的固定耗时或帧率。

持续检查覆盖 3600 万像素图、极宽/极高长图、三档质量、三种效果、空白文档、裁剪与旋转源页、追加、撤销重做、损坏文件恢复和重复保存。40 分钟完成 382 轮，每轮关闭后 URL 和 Worker 均归零，无未捕获页面异常。

期间发现节点数缓慢增长，堆快照证明文字节点引用来自自动化测试的 DevTools 元素句柄。测试改用不保留句柄的 locator 等待；没有把这一测试环境现象误记为产品泄漏，也没有保留无必要的渲染器生命周期改写。

最终源码额外完成 60 轮复测：挂载节点 4625–4636，监听器 768–771；主线程堆 12.0–13.4 MB，末次约 13.2 MB，URL/Worker 均归零。挂载节点数与浏览器内部 native 节点计数分别记录，后者包含字体、渲染和调试器保留的数据，不直接等同于产品挂载资源。

随后独立重跑 12 轮并抓取关闭会话后的堆快照，已无此前被保留的文字组件节点；测试释放问题得到复核。

## 责任边界

- 新工具由 `src/features/image-to-pdf/` 持有，原生 adapter 位于 `src/platform/image-pdf-runtime.js`，解码与元数据位于 Rust 图像域。
- 共享图像尺寸、分辨率、扫描像素与多行文字几何在 core；PDF Writer 在 shared；旧工具入口保留兼容转发。
- PDF 编辑器修改落在已有文件会话、操作、状态、页面、内容编辑、渲染与交互模块，不向应用组合根添加业务。
- 新增三个 Tauri 命令：`inspect_image_pdf_input`、`read_image_pdf_page`、`open_image_pdf_result`。沿用原有分块 PDF 输出命令和输出根；不新增用户存储键或 CLI/MCP 工具。
- 更新中英文、首页、帮助、工具统计、当前未发布 changelog、架构和维护说明。TIFF 相关许可证通知已加入安装资源清单。

## 边界与未覆盖环境

- 图像 PDF 最多 100 页，单文件 64 MiB、合计 256 MiB，输出 100 MiB；单图最多 4000 万像素，处理画布最多 1600 万像素。高分辨率选项不能恢复模糊源图的细节。
- 浏览器预览不支持 TIFF，桌面端支持列出的常见编码；特殊 CMYKA TIFF 明确提示转换格式。
- 扫描效果是外观处理，不包含 OCR 文字层、自动透视矫正或裁边。
- 现有 PDF 原文替换仍属于视觉覆盖，原文字可能被提取，不作为敏感信息脱敏；界面已有相应提示。
- 浏览器验证、模拟 IPC 桥接和真实 Rust 函数测试分别记录，没有把它们称为完整安装版 WebView2 实测。本轮没有制作新安装器。
- 保留已有的大 chunk、浏览器 crypto externalization 及构建环境提示；未把 warning 隐藏成通过结果。CLI 干净安装出现的既有依赖弃用提示不属于本轮新依赖。

## 建议验收顺序

1. 在“V3.2新功能”和 PDF 分类打开图像转 PDF，添加三张不同方向图片，排序、旋转并导出。
2. 分别比较原彩、灰度、扫描效果，以及 A4 边距和原图纸幅；确认导出后的页数、方向和顺序。
3. 加入一个损坏图片，检查失败提示及移除后继续导出；试一次处理中取消并重新生成。
4. 不上传文件，直接新建空白 PDF，插入多行中文、图像和形状；旋转页面，拖动与缩放组件。
5. 删除图像后撤销，再复制页面并导出；核对图像、文字和页面没有丢失。
6. 保存后缩放、切页并返回，不应误报未保存；重新修改或重置后返回，应正常提示。
