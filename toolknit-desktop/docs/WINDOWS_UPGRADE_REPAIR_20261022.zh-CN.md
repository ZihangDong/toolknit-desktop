# V3.2 Windows 覆盖升级修复

日期：2026-10-22。状态：修复和验证完成。分支 V3.2，版本 3.2.0 未发布。责任边界为 NSIS 模板、升级辅助逻辑和安装器测试；不改应用数据格式、Rust command、CLI/MCP 或产品版本。

## 已确认的原因

旧代码把多个不同故障统一显示为“无法卸载”，且存在两个可以在本机隔离复现的误报：

1. 卸载结束后检查新版 `$INSTDIR` 下的主程序。旧目录已经卸载干净，但用户选择的目标目录仍有同名文件，就会报告失败。
2. 在读旧版厂商注册表之前清除错误标志，随后直接执行卸载。厂商记录缺失所留下的错误标志能污染本次执行结果，旧程序已删除仍返回失败。

修复前的最小原生 NSIS 复现中，这两项均为旧文件不存在、父安装器退出 2。证据位于本机忽略目录 `tmp/upgrade-native-5c0688ff721b4d84ab9ceafbdf39d199/results.json`。复现卸载器是隔离桩，不是用户的实际旧版本安装器。

同时发现并修补：旧卸载命令未指定安装范围；依赖厂商记录拼接 `_?=`；半秒等待不能确认主程序文件已经释放；卸载主文件失败仍继续清除安装记录；仅被动模式读取不存在的单选控件；需要重启的卸载退出码也被当成普通失败。

## 修复行为

- 从旧 `UninstallString` 确认卸载程序与旧目录，兼容引用路径、中文空格路径和旧的未加引号路径。命令缺失时依次参考 `InstallLocation`、厂商安装路径；拒绝畸形或盘符相对路径，不执行任意未知卸载程序名。
- `/CurrentUser` 或 `/AllUsers` 明确传入旧 NSIS 卸载器。升级传 `/UPDATE` 保留数据和自启动，`_?=` 的旧目录作为最后一个参数；单独选择卸载同版本时不使用升级模式，也不继续装回来。
- 执行前立即 `ClearErrors`，执行后立即记录启动错误。区分取消、启动失败、非零退出、主文件残留以及 MSI 需要重启；不拿新目录的文件判断旧版结果。
- 等待主程序文件可删除，最多约十秒；暂时占用可恢复，持续占用或权限问题提供重试/取消。新卸载器在主文件删除成功之前不运行清理钩子或删除安装记录，避免剩下程序却失去修复入口。
- 旧版卸载返回 3010/1641 时停止本轮安装，要求用户自行重启后再安装，避免待删除旧文件在重启时连同新文件一起消失；不主动重启电脑。
- 更换安装目录时，只更新精确匹配旧主程序的自启动项，其他安装目录的条目保持不变。
- 新失败提示包含阶段、退出码与旧目录，以及退出托盘、检查权限和修复缺失卸载器的建议，不再仅显示“无法卸载”。

## 环境限制与交付

用户确认曾在 ToolKnit 仍于托盘运行时遇到失败，但具体提示和旧版本尚不清楚。托盘运行意味着主进程尚未退出，可能造成文件占用；上述后台进程升级测试已通过，但不能据此断言用户当时的唯一原因。真实杀毒软件拦截、跨账户 UAC、系统级权限拒绝及真实重启仍需要对应机器复测。

临时 QA 安装器仅用于隔离验证，不是给用户升级的测试包。此前 `20261022-000123` 测试包不含这次修复；修复任务结束时未打包，随后按用户要求生成下述测试包。未提交、推送 GitHub 或发布。
