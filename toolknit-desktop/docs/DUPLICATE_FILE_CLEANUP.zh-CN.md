# 清理重复文件维护说明

## 范围与流程

V3.1 新增本地 Windows 清理工具，只判断文件内容完全相同，不判断相似图片。参考 [Czkawka](https://github.com/qarmin/czkawka) 和 [fdupes](https://github.com/adrianlopezroche/fdupes) 的分阶段筛选思路，扫描算法未复制其代码，未引入新的扫描依赖。

“选择单个文件夹”或“选中全部文件夹” → 选择常用后缀 → 开始扫描 → 查看重复组并选择清理项 → 确认 → 移入回收站 → 查看成功/失败结果。全部文件夹模式枚举固定磁盘内允许扫描的目录，不包括受保护内容；点击范围按钮不会自动开始扫描。默认勾选文档、图片、音频、视频、压缩包共 42 个后缀，可逐项调整或全选/清空，不支持任意后缀。两种范围共用扫描上限、进度和取消流程。

初始所有副本均显示“已保留”，不选择任何清理项，不显示结果复选框。点击状态按钮逐份切换“已保留／待清理”，每组最多选择 N−1 份；选择最后一份时保留原状态并给出警告 Toast。支持组内“本组全部保留”和“保留一份，选择其余”，以及全局相同操作；全局操作包含当前搜索或分页之外的所有组。批量保留一份时采用仍保留的参考文件，初始参考为修改时间最早的一份，仅作建议，不能证明它是原件。用户选择原参考文件清理时，自动改用另一份保留文件；清理请求仍携带一个有效 `keep_path`，额外保留项不进入删除列表，无需修改原生命令契约。

结果按潜在可清理大小降序排列，手风琴首组默认展开，选择、分页和语言切换保留展开状态。分组和组内分页采用带无障碍名称的图标按钮，完整路径独占一行，文件定位和保留按钮固定于下方右侧。扫描按钮悬停保持主题对比色，取消扫描为纯文字；文件类型中心点有缩放/淡入淡出过渡。范围、扫描、选择、保护、定位和清理反馈复用共享 Toast，支持双主题和双语；清理前使用确认弹框，确认后关闭弹框并进入内容区遮罩。

清理遮罩覆盖侧栏与结果区，导航栏始终可用。白天为纯白背景、黑色内容；深色为纯黑背景、白色内容。复用扫描曲线动画，显示原生校验/回收阶段、实际已处理百分比、已验证/成功/失败数、当前文件名及耗时。停止仅阻止后续工作，已排队的当前批次可能完成。结算在同一遮罩展示全部成功、部分失败、全部失败、已停止或状态待确认五类结果与 SVG 动画；失败详情使用安全文本并最多展示 50 项。通信异常不推断文件是否已移动，只显示最后确认的计数。返回上一页淡出遮罩并清空范围、结果、选择、搜索、分页与进度，恢复可交互的初始页面；文件类型与递归选项沿用重新打开时的既有规则。

大小统计明确为“移入回收站大小”，不是已释放磁盘空间；工具不会清空回收站。

## 模块与复用

| 模块 | 职责 |
| --- | --- |
| `src/features/duplicate-file-cleanup/tool.js` | 懒加载入口，注入已有应用服务 |
| `template.js` | 可信模板，复用工具页 topbar |
| `controller.js` | 选择、分页、扫描和弹框编排，隔离旧会话结果 |
| `cleanup-view.js` | 内容遮罩、真实进度、结算、停止/返回、焦点与动画资源 |
| `core.js` | 保留项、选择、汇总、清理计划和结果更新，无 DOM/平台依赖 |
| `file-types.js` | 常用后缀分类，与原生允许列表保持一致 |
| `scan-animation.js` / `shared/curve-loading.js` / `shared/rose-curve.b64` | 按需加载曲线动画、双主题、本地双语一言及资源释放；旧入口兼容转发，PDF 转 Word 复用相同动画 |
| `duplicate-file-cleanup.css` | 专属布局、低高度滚动和双主题，沿用清理工具基础样式 |
| `src-tauri/src/native_runtime/duplicate_files.rs` | 遍历、分阶段校验、独立扫描会话及回收站执行 |
| `duplicate_files/protection.rs` | 只读查询注册表中明确的安装目录，按路径组件保护 |

导航、弹框、生命周期、背景和文件定位复用现有 shared/app/platform 服务。文件行的打开目录按钮传入完整文件路径，由 `output-runtime` → `open_path` 让 Explorer 选中文件。原生端沿用 `cleanup_guard` 与 `IFileOperation` 回收站实现；`system.rs` 的 `RecycleBinBatch` 复用 Windows 回收接口，独立的重复文件会话注册表防止普通清理命令绕过保留项校验。新业务不进入应用组合根。

## 命令契约

| Tauri command | 参数 | 返回 |
| --- | --- | --- |
| `scan_duplicate_files` | `scanId`, `rootPath`, `recursive`, `allDrives`, 可选 `extensions` | `scan_id`, `root_path`, `groups`, `progress` |
| `cancel_duplicate_file_scan` | `scanId` | 停止后续工作并撤销清理权限；已停止会话在有效期内仍可只读查询进度 |
| `get_duplicate_file_progress` | `scanId` | 原扫描字段，以及 `cleanup_stage/total/verified/completed/succeeded/failed/bytes/current/elapsed_ms` 清理字段（均带 `cleanup_` 前缀） |
| `recycle_duplicate_files` | `scanId`, `selections` | 原有 `moved_bytes`, `items` 逐项结果，新增 `cancelled`, `unprocessed`, `elapsed_ms` |

组成员为 `{ path, name, size_bytes, modified_at }`，清理计划为 `{ group_id, keep_path, paths }`。路径必须出自本次原生扫描，不能由前端任意构造。工具入口 `duplicate-file-cleanup`，overlay 为 `duplicateFileCleanupOverlay`。无新增持久化 key、公开事件或 CLI/MCP 能力。

## 判重与保护

后缀过滤与跳过空文件 → 大小分组 → 大文件头尾各 4096 字节抽样 → 完整 SHA-256 → 逐字节比较。8192 字节以内抽样阶段读取全文，复用本次扫描的完整摘要，避免再次读取；唯一大小的文件不进入哈希阶段。相同大小组达到 16 项时使用最多两个哈希工作线程，减少磁盘争用；最终比较复用保留候选的打开句柄。文件名与扩展名不参与内容判重，但候选必须属于所选后缀。

`extensions` 省略时使用全部 42 个常用后缀，空列表或不支持的后缀拒绝扫描。原生规范化大小写，前端/原生列表由契约测试核对。缓存仅属于本次扫描，不持久化用户路径或哈希。两份 4 字节重复文件的夹具累计读取量由原流程 24 字节减少为 16 字节；这不代表全盘扫描的固定提速比例，实际效果取决于磁盘、目录规模与文件类型。

普通文件夹模式不接受系统盘根目录；全部文件夹模式会枚举 Windows 固定磁盘，但仍跳过系统/程序目录、AppData、缓存、开发依赖/构建目录、云占位、只读/隐藏/系统文件、符号链接及硬链接。额外只读查询 HKLM/HKCU 卸载登记的明确 `InstallLocation` 并排除这些安装目录；不根据卸载程序位置推断父目录，不保证识别未登记的便携软件。只读扫描不修改源文件。回收前校验完整清理计划，确认每组保留项有效、不在删除列表，重新检查文件身份、修改状态和内容，并在处理该组时持有保留项只读句柄。失败项保留在结果中，已成功移动的项移除。

清理在工作线程内初始化一次 COM，跨重复组聚合最多 32 个已验证候选，再交给同一次 `IFileOperation` 执行。保留项句柄一直持有到所属批次结束，Windows 下禁止写入/删除共享；队列入站前再检查保留项与候选身份。逐项检查源路径是否消失，失败项仅在文件仍存在且重新校验通过时尝试单独回收，不回退永久删除。取消时未尝试的候选计为未处理，已提交批次仍可完成。

64 组、每组两份 8192 字节文件的 Windows 临时夹具对比：逐份回收 1303ms，32 份批量回收 538ms，均保留 64 份参考文件。此结果仅为本机小文件证据，不代表大文件或全盘固定提速；文件内容重验仍可能受到磁盘速度影响。复现：设置 `TOOLKNIT_DUPLICATE_RECYCLE_BENCHMARK=1` 后执行 `cargo test --manifest-path src-tauri/Cargo.toml duplicate_files_real_windows_recycle_keeps_original --lib -- --nocapture`，仅使用程序新建夹具，不操作用户文件。

回收站移动使用已有系统 API，没有永久删除回退。候选文件句柄关闭、最终检查与按路径移动之间仍有短暂竞态窗口，不能视为文件系统原子事务。取消不能撤销已完成的移动；用户可在回收站恢复，工具不自动清空回收站。

## 上限与生命周期

- 不再按目录条目数截断扫描；未选类型和目录只计入真实访问数。最多记录 100000 个符合筛选条件的普通文件，结果容量同步为 100000 个成员；只有遇到下一份超出容量的有效文件或确认副本时才判定截断，单独文件不占重复结果容量。超大组可返回已确认的部分成员，仍至少保留一份。限制原因仅在扫描结束后展示，并显示“部分扫描结束”，不能把部分结果表述为全盘扫描完成。
- 会话有效期 30 分钟，最多 32 个活动会话、4096 条取消记录与会话合计；过期或变更后重新扫描。
- 原生扫描使用 `spawn_blocking`，前端每 600ms 查询实际进度，不显示虚构百分比。
- 加载动画源自用户提供的 MathCurveLoaders 玫瑰曲线，保留 MIT 许可；白天黑/浅灰、深色白/深灰，复用共享动画帧策略和生命周期。后台暂停，减少动态效果时静态显示；一言来自本地中英文文案，不发起网络请求。
- 手风琴通过网格高度、透明度和位移过渡展开/收起，只渲染展开组的当前分页；收起后立即设为 inert，在高度过渡完成后释放文件行，减少动态效果时直接释放。展开区保持双主题反色及高对比度按钮，组间使用 1px 灰色细分割线。
- 返回、Escape、工具切换、pagehide 与 dispose 统一取消原生任务、清理监听/计时器/背景并处理焦点、inert 和 aria 状态。过期任务不能向新会话写入结果。
- 浏览器预览展示 UI 并提示需要 Windows 桌面端，不执行本地目录扫描或删除；“选中全部文件夹”必须安装 Windows 测试包验证。

## 验证方法

在桌面端目录运行 `npm run test:duplicate-file-cleanup`，覆盖核心选择/汇总/清理计划和模块集成契约。`npm run test:duplicate-file-cleanup-browser` 使用原生桥接夹具覆盖双主题/双语、桌面/窄窗口/低高度、搜索与分页、保留项、定位路径、确认和部分失败、取消/关闭重开；截图放在忽略的 `tmp/` 中。

原生专项：`cargo test --manifest-path src-tauri/Cargo.toml duplicate_files --lib`。覆盖内容判重、头尾相同但中间不同、空文件、递归、取消、伪造计划、文件变更、保留项缺失、并发互斥、部分失败、普通清理注册表隔离、Windows 硬链接/只读跳过和真实回收站临时夹具。

同时运行项目 architecture/release/security/CLI/build 门禁和严格集成审计。浏览器模拟桥接与 Rust 原生夹具不替代完整安装包、不同 WebView2/高 DPI 或超大目录的 Windows 用户实测；不要把未验证环境写成已通过。
