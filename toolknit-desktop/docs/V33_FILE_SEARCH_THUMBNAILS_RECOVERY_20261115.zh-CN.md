# 文件搜索：胶囊恢复与图片缩略图

2026-11-15，3.3.0 未发布。本轮基于 `d2c52ab`，用户反馈展开/收起后偶发空白胶囊，以及图片只有类型图标。

## 修复与责任

- 原生重复收起会推进 generation，却不启动新动画；前端仅按旧 generation 的结束通知撤销 `fill: forwards`，可留下变形层。真实 WebView2 的重复收起回归在原实现中失败（动画残留 1 个）。原生增加 `settledGeneration`，前端在新状态、中断、隐藏和结束时释放旧层；结束通知丢失时有界读取快照补查。位于 `auxiliary.js`、`windows.rs`、`window_animation.rs` 和 `mod.rs`。
- `results.js` 共用主窗口与胶囊结果组件，图片使用 48 px 预览格，保持行高 74 px、文件名/后缀、筛选、排序及唯一的资源管理器定位按钮。其他文件保留原彩色类型图标。
- `thumbnails.js` 只调度当前虚拟窗口，最多 2 个请求、64 条小图缓存。切换查询、关闭、暂停和销毁使旧回调失效并取消等待；忙状态有限重试，IPC 不返回也有截止。分页/滚动不装载全部匹配图片，不靠全局图标刷新更新缩略图。
- 原生 `thumbnails.rs` 校验当前入口、结果 ID、租约及索引中的真实路径，不接收前端任意路径。原图读取、图片解码及 Shell 缩略图 API 在普通权限的 `filesystem_worker` 子进程执行；现有高权限 NTFS 协议不增加读取正文的能力。换查询、切换模式及退出取消相应请求，Windows Job 随父进程退出回收。

## 图片与文件边界

- 输出最长边 128 px 的 PNG，单条不超过 72 KiB；前端只接受受限 PNG data URL。
- JPG/PNG/WebP/BMP/GIF/TIFF 使用已有 Rust 解码器；相机 EXIF 方向在缩小前处理，动图/多页图只预览第一帧。常用栅格格式优先直接解码，避免 Shell 缓存或扩展阻塞小图。HEIC/AVIF/ICO/PSD 可尝试系统已有解码能力，缺少对应组件则保留类型图标。SVG 使用隔离的 resvg 静态渲染，输入限 2 MiB/1 万 XML 节点，禁止外部图片/字体/DTD，不执行脚本；内嵌栅格图另有尺寸上限。AI 仅尝试系统已有缓存。
- 原图输入不超过 64 MiB，Rust 栅格解码上限 2400 万像素、分配预算 128 MiB。子进程每次最多 3 秒，Windows Job 将单进程提交内存限制为 256 MiB，并使用低于普通的进程优先级；有取消与并发上限。不可读、损坏、超限、离线或云占位文件回退图标，主结果和定位动作继续可用。
- 检查普通文件、各级目录链接/重解析点、云召回标记及已打开句柄的最终路径；不主动下载云文件，不修改源文件、不持久化缩略图、不上传。索引仍只保存文件元数据；帮助页中英文同步说明按需读取图片的例外。
