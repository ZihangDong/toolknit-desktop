进一步支持三条明确横线围出的“序号＋长文本”表格：有界合并相接线段，保留原始双线和真正的线位；明确序号表头、从 1 开始的连续行号、稳定正文列和完整格内归属同时成立后才建表。折行跟随当前序号，不把普通编号列表、任意双栏正文、断裂线段或内部图像强行转表格。字体映射修复新增原操作 UTF-16 范围；拆格时每项修复只归属一次，明确引用原操作及原字形编号，包含不绘制的空白证据，避免复制整段修复记录或假称子格局部编号。

实际 23 页报告恢复六张序号表格、一张示例表及附录标签表，共 168 格。示例表须有上下原始横线重复的唯一内部列端点、明确 Examples 表头、短标签和对齐正文；无表头的标签表要求恰有两条原始外线、重复列端点、粗体短标签及常规正文，折行标签仍属原行，不凭宽空隙猜列宽或补造表头。原稿 PDFium 路径边界、可见行标签和独立字体参考与实际 DOCX 逐格核对，168 格内容均匹配。附录中原稿未映射的一个粗体连字符另用源 CFF 轮廓和本机字体独立比对，F1 约 0.99757，advance 差约 0.086 字体单位，不作全局字符替换。WPS 各格局部前景 F1 最低约 0.98985；附录 1,310 个实际显示字符逐项匹配，基线 P95 约 0.297pt，标签最大同为 0.297pt，六个非关键正文字形最大偏差 1.601pt 单列保留。整篇其他质量项继续验收，八张表的局部通过不追加整份证书。

72 个原稿序号字形与实际 WPS 输出逐项核对，最大基线偏差约 0.755pt，横向原点偏差约 0.129pt。同次分析的原样/清空八表副本保持 168 格及 23 页：格内原生文字为零，144 DPI 下表格外扩 2pt 之外显著变化像素为零，17 个未编辑页面的数据完全相同。八处删字范围另与独立原稿隐藏文字后的图形核对，没有额外残字；避免只检查“没有可提取文字”而漏掉旧字图片，也不以两次重新解析的内部字体编号差异冒充编辑漂移。

附录原稿还有两段真正不可见的白底白字表头。仅在完整精确字形、纯白填充、白色页面且没有早先文字或不明绘制相交时排除；白色描边文字、半透明、局部深色、未知图像和背景覆盖继续保护。独立原稿 288 DPI 检查两处均为零非白像素；原始正文与这些不可见标题保持区分，避免空白回退图片挡住原生表格。

长表格段落的末端余量同时检查自然字体宽度和最终序列化 run 的原点、字号、缩放及 twip 字距。实际国家列表的末逗号含约 5pt 不可见空白，先前导致整词换行、末行被固定行高裁掉；修复后该格局部 F1 约 0.99972。仅在全部精确字形笔画已位于格内时授权有界末端余量，不缩字、不改网格，不放宽垂直容量检查。

真实论文 F16 第 6 页的 6 行、10 列表格已生成原生 Word 表格。60 格文本按原稿图像独立核对；初读小图的三处人工误读通过高分辨率原稿裁图纠正，未修改产品输出迎合误读。独立 LibreOffice 回读中，每格前景 F1 均为 1.0000（沿用 1pt 容差，并非逐像素完全相同）。删除一格数值后，旧字消失，外扩 2pt 之外变化为 0；该结果不代替其他复杂表格或阅读器的验收。

另修复真实报价表中，表头笔画在格内却被 WPS 提前换行并裁掉末字的问题。行末全宽 advance 超出格内可用宽度时，仅对精确笔画均在格内且空白超出量不超过半字号的行提供有限末端余量，不缩字、不改变格宽、边线或垂直容量。两份完整报价表共 40 格（含七列合并格）已按原稿独立转录核对，再直接检查 DOCX 的文字、行列与合并。来源位图网格与 Word 网格的最大偏差分别为 0.267pt、0.183pt；各格最低外观 F1 分别为 0.99974、1.00000。四份真实表格补做本机 WPS 删字导出，旧字残留及外扩 2pt 之外变化均为 0。

独立原生 Latin 变量在明确字体、完整笔画框、唯一来源及测量比例均可信时，于资产与布局前恢复为普通文字。复杂结构、扫描、未知编码、花体与装饰仍保留原图；不把单字母计成完整公式。固定文档新增 118 个普通可编辑变量，WPS 局部对照 118/118 达到 0.95，最低 0.96429。三份代表文档的变量另经 WPS 原样回存和改一字回存，六次均只发生预期文字变化，活动字体、字号、字重、斜体、颜色、字距及缩放保持。含 OMML 的文档不能将 `Content.Text` 下标当作原生 Range 地址，本轮已改用格式化 Find 绑定实际目标与原页。

普通变量在额外 LibreOffice 回读中为 116/118 达到同一局部门槛，仍有两个未过线，最低 0.91556；这不改变下方 OMML 的跨阅读器限制，不能声称所有数学内容均已兼容。

进一步修复 OCR 单字的文字框裁切：OCR 保存的 advance 是笔画宽度，全角左括号的左留白较宽，末字若被压成笔画宽，WPS 会把已写出的字形全部裁掉。仅对精确 OCR 单字的末端保留至少字体 advance；不改变前面的字距、下一来源原点或多字符塑形，Canvas 与 Writer 继续同源。F11 第 1 页一个在修复前独立确定的左括号范围，原稿 288 DPI 笔画像素为 203，旧结果为 0，修复后为 217。四份扫描文档中，PDF 文本元数据存在但字框内无实际墨迹的诊断项由 53 降至 0；不是把这些字符称为 53 项独立语义验收。F14/F15 也追加了真实输出逐字墨迹检查，均无空绘字。

继续校准固定行高的 OCR 基线。受控字体、字号、字重和位置小样显示，Calibri 的 Canvas hhea 居中计算会使 WPS 基线偏移最多约 3.49pt；同一载荷在 LibreOffice 中最多约 3.50pt。精确 OCR 框改按序列化固定行高的 80% 定位，代表字体小样中的 Calibri 误差分别降至约 0.11pt、0.05pt。原生文字和含图片的行保持原度量规则；小样用于定位根因，不计入 20 份语料。

字体匹配继续使用原有小图和门槛，但实际子字形的字号、基线及横向比例改用与 Writer 同源的 1000px 连续轮廓度量，不再由签名小图的取整像素决定。保留原粗略行字号用于邻近字体提示和回退，缓存及画布预算不变。两份短扫描方案的实际笔画边缘 P95 从约 1.5pt 降到 0.75pt，数字最大偏差从 2pt 降到 0.75pt；金额、单位及标题关键字形最大偏差不超过 1pt。少数非关键字形仍有 1.25pt 的边缘差异，保留记录。

完整删除测试还发现标题横笔被扫描线条检测误判为表格线，旧图因此残留。新增有界的单字线条归属判断：仅排除高置信度水平文字内、受 CTC 单字范围约束且无竖线交点的短横线；保留跨字线、下划线、网格交点和原生矢量线。两份短扫描方案删除全部文字后，本机 WPS 导出分别从 3,323、3,321 个旧墨迹像素降为 0（288 DPI），没有剩余文字。两份各 12 个编辑目标逐个追加“123”和删除，原字符样式与原场景保持；WPS 原样和改字回存共四次也通过。

合同比率新增原图校验：只在三个闭合圆环的位置、宽高比例和本地字形优势均成立时，把误识别的百分号恢复为千分号。CTC 错落到前方填写横线时，按有界邻域独立核对；只证明符号就只修正文字，不伪造整行字框或样式。普通百分号、断环、低置信度和歧义候选保持原路径。

低置信度彩色正文不再仅测量中性抗锯齿边缘。完整非红色笔画需通过字体形状与墨迹占比验证，才能去除原字；短标签复用附近已验证字体。未证明的彩色区域不叠加新文字，保留原图，红色印章与原生线条继续受保护。扫描标题的竖线残留、少数 CTC 字框和标点误识别仍单独保留为未完成项，不能以整页外观高分掩盖。

保留图像的未确认 OCR 候选仍进入来源账本，由背景图持有，不漏出统计分母。编码器必须核对来源类型：只有全部属于未确认 OCR 候选的照片，才沿用原照片编码；缺失来源、已确认文字、公式、表格和灰阶扫描继续保留无损保护，避免元数据补全使 44 页照片方案超出现有限额。符号校正由 OCR 显式开启，原生已知文字的字体校准不得改字。

公式使用严格默认策略：经字体、结构和几何门禁的简单等式，以及已验证字体、最多 8 个来源字形的一级短上下标可尝试 OMML；另有最多 16 个来源字形、一个具名极限且无嵌套结构的保守路径。短上下标和简单极限沿用来源基线框，多字形平面等式使用紧凑测量框。少量已核实的 Cambria 单条 ASCII 等式沿用原生来源框，避免尾部空白使测量框错误拒绝。未知字体、未证明的多字符指令、嵌套上下标及其他复杂二维结构继续保持原图。扫描公式明确标注 raster OCR 来源。内部实验能力仍保留，不把 AST 可解析或宽度估算通过当成阅读器还原成功。

此前策略在固定原稿中多保留 48 个可编辑上下标区域和 1 个简单极限区域，加上原有等式共 61 个原生数学区域；实际 WPS 完整文档局部对照均达到 F1 ≥ 0.95，最低 0.97959。后续只为精确原生笔画、同一 Cambria 斜体、显著较小字号及上下边界共同证明的浅下标增加窄路径，支持经过核对的二至三字母基底；不降低其他字体的通用下标门槛，也不扩张扫描来源。ASCII 数学文字可保留原 Cambria 字体，非 ASCII 字符的数学字体策略不变。

实际报告新增 `b_i`、`e_i`、`nb_i`、`mc_i` 和单条 `BI = A + SN`，当前完整语料共 66 个原生数学区域。五处均经独立原稿标注、DOCX 的四个 `m:sSub`/五个 `m:oMath`、实际 23 页 WPS 输出核对；最大基线差约 0.478pt，横向原点差约 0.834pt。完整页面中固定范围的局部 F1 均为 1.0000，区域外显著变化为零；隔离探针的最低 F1 为 0.97266，裁图边缘的邻文分别说明。它们是五个完整小区域，不能称为 66 条完整公式或整篇语义通过。CLI/MCP 的显式实验参数不变。

具名极限修复针对 PDF 将右括号、等号和 `max` 合并到一条文字指令的情形。仅在原生字形位置、UTF-16 偏移、文本和完整覆盖均能证明时，Writer 局部拆分该指令；原场景、来源账本和 AI 请求编号不改写。拆分必须产生有几何证据的限标关系，不能借机改写无下限的平面等式；追踪和衍生对象计入既有工作内存预算，最多 200 个字形。缺字、伪造偏移、越界、基线变化、跨 token 的单个字形或编号冲突均保守拒绝。

独立原稿标注核对了 F18 第 4 页四行等式（4）的首行 `C(G) = max_D V(G,D)`：D 应位于 max 下方。旧内部原生实验路径把合并指令作为下标基底，局部 F1 为 0.82342；旧桌面默认将它保留为图片。修复后才加入默认原生输出；原稿独立范围的 WPS F1 为 0.98759，范围外显著变化为 0。直接解析 DOCX 核对了 max、D、符号顺序及原页归属；WPS 原样和改字回存后，这些关系和该范围 F1 均保持。它是公式片段，不计作整条四行等式通过。同一完整文档其余 180 个原生候选区域没有可测变化。

兼容性限制：当前 61 个数学区域在本机 LibreOffice 的局部回读仍未过关，仅 1 个达到同一局部门槛。页数和整体高分不能掩盖局部数学偏移，新增极限也未在该阅读器通过。数学路径目前仅完成 WPS 外观验证，跨阅读器兼容仍需修复，不能作为已经满足正式发布质量的承诺。

上游源码核对：实际验证程序为 LibreOffice 26.2.5.2（cd7284b4cbbf）。该版本对应源码和 `libreoffice-26-8` 分支均没有 `GetFontSizeInHalfPoints`；官方主线在 2026-09-22 的 [111a2ffc8be0](https://github.com/LibreOffice/core/commit/111a2ffc8be0) 才补上 DOCX 公式字号导入/回存。因此不能指望仅升级到 26.8 就修复本问题，也不能把公式默认 12pt 全归因于 Writer 的字号属性缺失。逐 run 字距和定位仍需独立检查；本轮只研究上游实现，未复制其代码、修改本机阅读器或调整产品依赖下载源。

照片按最终可见裁切进行保守编码并复用重复资产，文字、线稿、公式和不确定区域保持无损。44 页图文方案在既有 32 MiB 资产预算内完整生成约 27.4 MB DOCX。

新增 `core/partial-ruled-tables.js` 处理具有连续分区及重复数值锚点的稀疏表格。空值保留原列，跨行标签依据唯一且居中的水平分区，跨列正文依据原竖线分区；不能从未知空白猜合并关系。原横竖线只合并共线段，避免连成整表裁图而重新带回旧字。紧凑原生行距按可见笔画、原基线及实际阅读器有界校验，不改字号，不套用 OCR 度量。

`core/multi-header-tables.js` 仅在重复数值列、居中组名及每个下级列独立支持时恢复跨列表头，唯一且垂直居中的标签可跨行。控制表头层数、文字及分组预算；不把多级文字压成一行，也不把数值型样本量注释错误拆成层级。`core/sparse-horizontal-tables.js` 单独处理具有至少两列重复数值、完整显式数值或短横线占位的单层表头；缺少占位或存在组行歧义继续回退。真正抬高的脚注可在原空白内调整无边线行界，字号、笔画和基线保持，仍须通过两侧单元格的实际容量校验。

### 定位原点与扫描行归属复核

定位框原先按父文本测量，Writer 却可能输出已经拆分的子词；前导空格在 Chromium 中具有负 bearing，造成页脚与图示标签错位。`adapters/text-layout.js` 现在统一实际子 run 原点，框位置、段落缩进、容量与游标共同使用；Node 的空格度量差异有独立回归。完整报告的第二页图示及页脚，实际 WPS 局部前景 F1 均恢复为 1.0000。
