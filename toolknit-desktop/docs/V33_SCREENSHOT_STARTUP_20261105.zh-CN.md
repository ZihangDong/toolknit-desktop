# V3.3 截图启动提速

2026-11-05，V3.3/3.3.0，未发布。本轮本地实现验证，不提交、推送或打包。

## 根因与改动

- 旧链路首次捕获后才创建 WebView，且每次固定等待 160ms；编辑器先等本地翻译状态，图片经 PNG/Base64/JSON 后再解码。
- 应用启动界面结束后延迟预热（快捷键已注册时）；进入截图工具也可预热。只创建隐藏、不聚焦的空 shell，不采屏、不读取 AI Key、不初始化模型。无 session 的 boot 返回 prepared。
- 同一创建锁协调预热和真实调用。先完成窗口定位/尺寸，再发布截图 session；就绪在原生主线程再核对 ID。旧同会话通知不重复解码，取消先撤销会话再隐藏窗口。
- 无需隐藏自身表面时不等待；确实隐藏时使用 DwmFlush 及短展示保护，失败/超时回退原有等待预算。合成器工作最多一个，避免驱动卡住后任务堆积。
- 新 quick_screenshot_image 仅允许 screenshot-capture 读取匹配的活动 session；只返回内存 PNG，短锁获取 Arc、锁外复制，返回前再次验证。旧 boot 的 Base64 返回保留兼容。
- 前端检查 PNG 头、长度与图片尺寸；Object URL 在解码后释放，错误/取消清空图片，画布和标注资源归会话。翻译状态移到 ready 后，迟到结果不能覆盖手动语言或新会话。
- 仍使用原 GDI 捕获及无损 PNG。合成编码基准中，1080p 默认约 10ms、4K 约 41ms；单换压缩参数不足以解释主要延迟，未盲目改为 raw/GPU。

## 测量范围

- 原生隔离基准使用真实 WebView2/IPC/控制器和合成 PNG；测试窗口始终隐藏，禁止抢焦点。没有捕获、保存或上传用户屏幕内容。翻译 status 人为延迟 800ms，验证不再阻塞 ready。
- 基线 1080p：冷调用一次 1330.66ms；暖调用 5 次中位数 202.67ms。固定等待约 170ms，首次创建窗口约 999ms。这里统计到编辑器 ready，不能冒充物理屏幕首个可操作帧。
- 优化后的真实 WebView2 合成矩阵：预热后首次 127.76ms；1080p 后续 69 次中位数 46.56ms、p95 47.62ms；4K 30 次中位数 109.64ms、p95 111.56ms。销毁窗口后按需重建 158.15ms（进程/运行时已热，不代表全冷进程）。共 100 次会话加一次重建，像素、尺寸、旧 ticket 拒绝、重复通知、图片/画布释放及单窗口复用通过。
- 本机真实 GDI 抓屏与 PNG 编码另测 10 次：1920×1080，中位数 31.38ms、最大 38.60ms。像素只在内存中使用并释放，未保存或上传；这不是按键到屏幕显示的端到端数据，不能直接与合成矩阵相加。
- 不同阶段采用各自单调时钟，只比较耗时，不直接相减 Rust 与浏览器绝对时间。日志位于忽略目录 tmp/screenshot-*.log，不包含截图正文或用户路径。

## 验证与限制

- 专项像素/几何、二进制输入/大小/过期/解码失败/URL 释放和架构检查通过；空 session 请求明确拒绝。
- 浏览器合成桥双主题 16 项通过：预热、慢翻译、框选、OCR、保存转定位、重复通知、取消、失败恢复及无未捕获异常。未调用真实外部 AI。
- 完整发布回归 114 个 npm 脚本通过，包含安全 1,803 项、CLI/MCP 独立安装及实际文件转换。最终变更后再运行 focused、构建、架构和产物审计。
- 文件搜索真实配对 WebView2 回归通过：100 次筛选/折叠、动画反向、截图 guard 隐藏/不抢焦点恢复，较新的隐藏/关闭意图不被覆盖。
- 全量 Rust 最终通过：315 passed、26 ignored、0 failed；忽略项中的编码基准、截图启动矩阵、内存捕获计时及文件搜索原生回归已按本轮需要单独执行。最终架构/产物审计和 diff 检查通过。

本轮未测用户实际显示器上的按键到可见画面的完整延迟；4K 指合成像素尺寸，不是实际 4K/双屏/HDR/RDP 验收。真实桌面捕获只测内存路径，完整交互与用户设备体验仍需测试包验收，不能把隔离 ready 数值当作全环境保证。保留现有大 chunk/crypto/linker 非阻断提示。
