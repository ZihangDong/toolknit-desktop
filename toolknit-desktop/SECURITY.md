# Security Policy

## Supported versions

Security fixes are prioritized for the current `1.2.x` release line and the current development branch before release.

## Reporting a vulnerability

Please do **not** open a public issue for a potential vulnerability involving arbitrary file access, path traversal, code execution, credential exposure, unsafe dependency downloads, or user-data disclosure.

Use the repository's **Security** tab and select **Report a vulnerability** to submit a private report. Include:

- A clear description of the impact.
- Reproduction steps or a minimal proof of concept.
- Affected version, operating system, and configuration.
- Any mitigation you have already identified.

Do not include real API keys, passwords, or private user files in the report. Redact them or use harmless placeholders.

## Response targets

| Stage | Target |
| --- | --- |
| Initial acknowledgement | Within 7 calendar days |
| Triage and severity assessment | Within 30 calendar days |
| Fix and coordinated disclosure | Depends on impact and reproducibility |

We will credit reporters in release notes only with their permission.
